## 2 时间与日界的执行方案

每帧先处理输入/模式切换，再推进当前阶段，最后处理至多一个阶段结算。阶段转换使用单一入口，不由HUD、战斗导演和作物系统各自增加日期。

| 状态 | 白昼累计/当日计时 | 阶段计时 | 作物 |
| --- | --- | --- | --- |
| 普通白昼/静观 | 推进 | 不单独累加夜间计时 | 合条件增长 |
| 黄昏 | 停止 | 最多30秒 | 合条件增长 |
| 守夜 | 停止 | 战斗阶段推进 | 镜像不推进真实农田 |
| 暂停/灯下 | 全冻结 | 全冻结 | 暂停不长；灯下合条件增长 |
| 离线 | 全冻结 | 全冻结 | 仅保存时已种作物，最多720秒 |

黄昏超时睡觉、敲钟和场景切换同帧发生时，由同一个转换事务决定一次结果；已开始守夜不能再走睡觉分支。先完成结算、推进绝对日序号，再进入次日；持久化已完成的结算标记，重载不能重复跨日。

离线不能无限延长临时光效：仅按剩余有效时长贡献光照。夜苔离线时仍检查保存的季节，离线不触发换季。新迁移档没有可信时间基准时不补算离线。

## 3 纯守夜的完整启动方案

基础夜钟从第一日黄昏可用，位于母灯附近的可选岔路；用世界交互物提供基础材料兑换，不依赖第三盏灯后才出现的旅人。两者均不阻挡正常道路。

第一日白昼可探索、熟悉灯的开关和在不发奖励的训练预览中练习，不要求播种。初始守夜提供固定的基础镜像灯火和素引动作；不把弹药能力完全绑在真实露滴存量，否则玩家把2露滴用完后仍会失去战斗入口。

起调收入采用：完整结束一夜（胜或败）36夜露，主动弃场0；余温仍仅胜利1份。评级不增加材料收入。兑换只提供夜露→露滴/灯孢，2:1、零好感门槛、明确确认，不提供可循环套利的反向兑换。

新档路径：初始2露滴 → 第一夜36夜露 → 换12灯孢和6露滴 → 支付12灯孢+8露滴完成首次修灯。失败也有基础进展；弃场不成为无成本领奖按钮。

这是消除启动死锁的起调方案，不代表纯守夜耗时已与种植相差30%以内。完整路线需记录日历、夜露获取、兑换、每灯价格和解封，检查后段是否拖慢；不能用首灯模型代替完整主线平衡。

## 4 战斗结算 临时田与耗材

### 4.1 状态白名单

| 状态 | 胜 | 败 | 弃 |
| --- | --- | --- | --- |
| 镜像灯火/弹药/遮蔽物损失 | 丢弃 | 丢弃 | 丢弃 |
| 原真实作物和修灯状态 | 保留 | 保留 | 保留 |
| 基础夜露 | 起调36 | 起调36 | 0 |
| 余温 | 1，受季上限约束 | 0 | 0 |
| 实际产生的合格造田事件 | 提交 | 提交 | 不提交 |
| 实际产生的挂露 | 提交为可手采物，不直接加露滴 | 同胜 | 不提交 |
| 已消耗的光尘/附痕次数 | 按已发生事件保留消耗 | 同胜 | 同胜，不因退出退款 |
| 日历 | +1一次 | +1一次 | +1一次 |

败场仍保留实际做出的劳动成果，避免把旧“仅无余温”的低惩罚方向改成农田损失。造田、挂露必须由真实有效动作产生，不因进入/结束战斗凭空生成。

### 4.2 命中与同源次数

- 一次有效攻击有唯一`action_id`；命中至少一个合法目标或可造田格才扣1次附痕耐久，空挥不扣。
- 多目标、往返、持续接触的回调不能把同一动作重复扣成多次。同一次触发可以按兵器范围改变多个合格格，但露痕每次触发最多生成一颗露。
- 配方元素集合包含当前兵器元素即同源。同源每次有效动作触发；异源每两次有效动作触发一次。八次耐久最多8次或4次效果。
- 每次触发使用完整的布尔资格、整格范围、1露滴和规定寿命；不生成半格、半滴，也不把一个白昼减成半天。异源半次累积随该枚附痕保存，换痕不继承。
- 上述“减半=次数减半”是本轮可实施方案，解决原文未定义的异源效果；不是声称旧v16已经规定了该算法。

### 4.3 土壤范围与到期

固定苗床预算仍为五区46格。额外临时荒地从地图作者登记的候选格中选择，不能占道路、出口、墙体、水面、NPC站位或灯基座。起调每区同时最多4格额外临时床，退役床也占额度；这是附痕阶段的预算，不扩入切片A的12格。

夜间事件在进入次日日初时提交，`expires_day_index=当前日序号+1`，保留完整的接下来白昼和该日剩余阶段，到下一次日界到期。白天主动造田则到次日日界到期，提示“今日有效”，不承诺从任意时刻获得额外720秒。

同一格现有`active`或`retiring`许可不能通过重施、重复命中、切区或读档延长到期日；再次施痕只按短时效果规则处理。旧许可到期并完成清理后，新的合法动作才能建立新的种植许可。

到期处理：

1. 空的额外临时床清理；空固定床只撤掉临时效果，不删除原苗床。
2. 长效种植许可所服务的床有作物时，该许可转`retiring`：禁止换种/续期，只保护现有这一株。固定床和额外临时床都适用保株，但只有额外临时床占4格预算。
3. 保留这株的土壤与必要种植光照许可，取消+20%等附加增速；季节限制始终有效。未成熟继续按合法条件生长，错季则暂停；成熟仍需玩家手收。
4. 收获或主动移除后清理退役许可；额外临时床一起移除，固定床恢复普通判定。不会自动成熟、收获、兑换或把作物搬入背包。
5. 再次施痕不能给退役许可重置轮作权限。额外候选格清理后要重新产生合法造田事件才能再用；固定床按正常种植规则继续使用。

短时影囊痕8秒、雾痕20秒等瞬时光效照常到期；不能因保株而延长整片战斗遮蔽或额外增速。保留给作物的资格在预览中标“仅保护现有作物”，避免误认可以继续播种。

### 4.4 结算与领取去重

进入守夜保存`battle_id`、进入日序号、真实状态基线和镜像；局内只记录事件。结束时在临时副本里应用白名单，连同消耗、日界和已结算标记一次写入。只有保存成功后才把完整结算报告为完成。

写入失败保持待结算状态，重试同一事务，不能一边给奖励一边继续下一夜。正常退出已有待结算事务先完成；异常中断从保存的局内状态恢复，或进入明确的放弃结算，不能同时给奖励又退耗材。

世界动作和战斗动作都分配持久化的唯一`action_id`，效果以`source_kind+action_id+effect_id`标识，战斗来源另携带`battle_id`分组。白天动作不伪造战斗ID；生成挂露与该次耗材消耗一起提交。手采时“移除可采表现+增加1露滴+领取记录”同事务完成。重复交互、重复结束信号、同帧多碰撞、保存重进均只能领取一次。这里保障正常运行中的幂等，不承诺防止玩家手动回滚整份存档。

## 5 光场与附痕求值

统一解析器按以下顺序求值，生长、敌人和Tab预览读取同一份结果：

1. 先过滤过期光源、失效来源与越界效果，区分普通世界和战斗镜像。
2. 计算有效固定灯、临时光源与倒影的物理光强/来源；多来源取最亮有效值作为标量，另保留暖杏、月青、倒影标记。
3. 应用遮挡与雾的减光；同类雾取最强一层，不靠同一事件重复乘法叠成无限黑暗。
4. 应用明确的造影上限。造光已作为步骤2的临时光源参与求值；需要物理深影的局部效果在减光后把光强钳到最多0.10，严格满足小于0.15。多个造影上限取最小值，不依赖事件遍历顺序；同时造光/造影时仍按此顺序结算，不用恰好0.15承诺深影。
5. 合并附痕授予的种植条件。二向痕可以同时授予深影/暖光/双光种植许可，但不把实际光强伪造为同时亮暗；它也不自动令敌人同时追光又追暗。
6. 最后检查可种格、作物种类、季节资格；非冬夜苔和非春秋回声铃在任何光照下仍暂停。

必要边界：`0.15`不是普通深影、`0.6`不是普通暖光；`1×0.5=0.5`仍不适合普通月苔；相同事件重复到达不叠加；一个光源移除不误删另一个来源；二向痕到期依D02保株规则处理。

## 6 输入方案与界面验证

切片A沿用1/2选种。完整玩法接入时给一次简短提示，然后采用下列方案；所有动作可重绑，提示从当前映射读取。

| 功能 | 键盘/鼠标方案 | 手柄方案 |
| --- | --- | --- |
| 移动 | WASD/方向键；左键空地短距直走≤3格，不绕路 | 左摇杆 |
| 元素 | 1～4 | 普通操作时十字键四方向对应元素 |
| 种子面板 | B打开；方向键/滚轮选，Enter/E确认，Esc关闭；可点击种子卡 | Y打开；十字键选，A确认，B关闭 |
| 手账/族内器形 | J打开；焦点导航并确认 | Back打开；十字键/肩键换页，A确认 |
| 交互/引 | E/空格；左键选中可交互物，中键执行引（可重绑） | A |
| 冲刺/格挡 | Shift或双击地面方向 / K或鼠标右键 | RB / LT |
| 促长/移除 | Q/R或对应动作按钮；只在苗床目标可用 | LB促长；移除放种子/苗床上下文面板，避免与Y开面板冲突 |
| 光域预览 | Tab | 右摇杆按下 |
| 暂停/返回 | Esc | Start暂停，B返回 |
| 灯下 | F或暂停菜单；点物件 | 暂停菜单坐下；自动吸附，十字键换物件，A反馈 |

这是补齐入口的原型映射，J/B等为面板动作，不新增战斗技能键。UI捕获输入后世界不再响应；关闭面板的Esc不同时触发弃战。

世界优先级：暂停/模态UI → 灯下反馈 → 已高亮且在范围内的交互 → 当前场景的引动作。守夜不提供真实农田收获入口，交互仅作用局内装置；没有更高优先级交互消费该事件时，执行当前瞄准的引动作，敌人目标不会阻止攻击。每次事件只分发一条动作。

UI预算沿用两栏280px外宽；16px中文先按可用内容宽估16字左右，再实际测量。测试三档字体、两位及更长资源数、双语键位图标/按钮标签，不截断成本和条件。快捷键文字来自绑定，不能把“按1种月苔”永久写死在剧情表。

## 7 母灯 陪伴与性能方案

母灯的“永不熄灭”落实为真实经营层规则：不可手动熄灭；借光可以降低可借灯火，但保留基础78px有效照明，不额外出灯芯屑；等charge恢复满值后才继续凝积。UI说明“母灯守着这片光”。其守夜镜像不享受永亮豁免，否则母灯旁基础战斗永远无法失败。M0仍原样迁移灯开关，不能在格式迁移中偷偷改变这一玩法；母灯规则随M1内容版本启用，并明确提示旧档该灯被点亮。

灯下的原稿在“零后果”和“摸猫日上限+1”之间矛盾。本轮原型方案遵守零后果护栏：灯下摸猫只播放动作和声音，不增加好感、不使用普通摸猫的每日额度；退出后普通游玩的摸猫按原好感规则处理。旧“灯下日上限+1”不再作为此模式的效果。

灯下只接受六种装饰交互；隐藏HUD并不等于禁用世界输入，所以显式阻止播种、收获、促长、造田、领取挂露、交易和元素切换。需要做这些事情时先退出，不能在冻结日历中偷偷继续整套经营动作。

失焦原型方案：普通游玩默认失焦暂停；灯下失焦保持陪伴，系统休眠冻结并暂停声音，唤醒按灯下规则继续，不补推进日历。聚焦/失焦不等于退出；移动、Esc或菜单明确退出才恢复普通计时。坐姿记忆只保存本地灯/镜头偏好，进入时站在当前附近合法位置，不跨区传送。

动态重绘12Hz/8Hz与引擎帧率分别统计。对普通、灯下、失焦三种状态各测帧率、帧时间、CPU/GPU和音频，后台可限制渲染帧率而不拖慢音频和已定义的作物时钟。先报告同机对照，再定功耗目标；不再宣称“8fps所以不烫机”。

本节是对旧矛盾的明确原型方案，尚非实机验证结果。它不新增需要用户再次确认的开工审批。

## 8 分享与导出协议方案

### 8.1 灯语示意码

采用总9字符的协议初案：8个载荷字符共40bit，最后1字符校验；选择该方向与旧已定事项的“总9含校验”一致。它只显示固定模板的布局示意，不承诺精确表达任意装饰、所有作物种类或临时田。

| 载荷 | bit |
| --- | --- |
| 协议版本 | 2 |
| 区域ID | 3 |
| 固定苗床模板ID | 3 |
| 12个模板槽的作物分类：空/阴性/暖性/其他 | 24 |
| 该区最多4盏灯的开关掩码 | 4 |
| 配色预设 | 2 |
| 保留位，当前必须为0 | 2 |
| 合计 | 40 |

字母表明确为`ABCDEFGHJKLMNPQRSTUVWXYZ23456789`，恰好32字符，排除I/O/0/1；不再写“A-Z+2-7再删I/O”而只剩30个符号。大小写输入正规化，不接受未知字符。

按表中顺序从高位到低位打包40bit，再从最高位起每5bit映射一个字符，字符索引从0开始。初版协议字段取1；区域、模板、槽位和灯掩码顺序须一起登记，未登记组合一律拒绝。字段编解码测试向量使用`version=1`、其余位全0：载荷十六进制`4000000000`，含校验字符串`JAAAAAAAJ`；它只检验位序与校验，不表示未登记模板已经可导入。

校验初案是前8个符号值按位异或，结果仍为0～31；能检出任意单字符替换，但不保证检出字符交换，不用于防篡改。未支持版本、非法区域/模板、非零保留位、无效灯掩码拒绝显示，不访问存档状态。模板一旦发布不可重编号；需要精确复原更多内容时另升协议，不向旧9字符塞入超额信息。

### 8.2 完整存档箱子

独立协议初案：4字节ASCII魔数`MOSS`、2字节小端容器版本、4字节小端JSON字节长度、32字节SHA-256摘要、UTF-8 JSON载荷。具体偏移、版本与检查以[存档契约第8节](save-contract.md#8-导入导出协议初案)为主定义。摘要覆盖实际载荷字节，用于发现传输损坏，不构成防手改或身份认证。

载荷不超过当前1MiB上限；导入先检查魔数/长度/摘要，再检查容器版本和garden版本，最后用同一存档校验器构造临时状态。只有全部通过，才备份当前有效档并原子替换；高版本、截断、追加垃圾、类型错误均不改变原档。

协议在功能实现前还需固定测试向量并验证编码往返。这里给出完整格式方案，不能声称既有游戏已经兼容此格式。

## 9 灯谱与解封的补充处理

已定第二轨成本减1、最低1继续保留。撤销“每节点原价1却能8→6”的推导；M2/M3前输出逐节点表：ID、前置、原价、所属轨、第二轨实付、免费途径、实际点数事件。验收对三条路线分别累加，而不使用重复的总点数口号。

旧深影囊携带数等效果不进入新实现。替换方案先围绕现有能力：`deep_pocket`用于非战斗备用附痕、`mist_trail`调整雾痕持续、`mist_step`调整雾内移动条件；不增加第二附痕槽。具体参数作为节点原型表提交，不伪装成原v2已经批准的数字。基础穿矮栅栏始终属于冲刺本体，`grass_step`不得再锁住它。

解封依赖采用“先接触、再确认”方案：融合台可零收益试配一次再解封，导光苔枝提供教学试用后再取得携带能力；战斗向证明只能要求已可使用的基础动作，不要求先拥有要解封的物品。夜钟从D01入口直接可用，不再“三灯全亮后才能取得第一笔战斗收入”。

最后对全部八件器具做两个无环遍历：禁止播种时仍有路，禁止守夜时仍有路。每个节点至少一条不依赖技巧的途径，循环前置和只有“同理”的空表格都算未完成。

## 10 实施顺序与完成判据

1. **M0**：先按存档契约做格式迁移、异常回退和新旧共存检查；不动种植参数。
