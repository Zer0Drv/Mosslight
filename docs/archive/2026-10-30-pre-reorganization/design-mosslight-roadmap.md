# 苔灯镇 · Mosslight 设计路线图

> **状态**：设计稿（design-only）。本文档中所有系统**均未实现**，代码保持现状。
> **版本**：**v6**（2026-10-30）。v5 加入联动矩阵 / 光尘 / 四途径 / 封印；v6 定稿联动补强、确立自动化边界（巡灯路线·离线生长·静观）、以夹页与灯路图替代任务日志、器具封印改双途径。
> **依据**：10 轮设计讨论 + 对现有代码的实测（全部脚本合计 1676 行）。
> **用途**：本文档是唯一的裁决依据。任何新想法进来，先对着第 2 节「三条护栏」和第 8 节「决策变更记录」检查是否冲突，再决定做不做。
> **最后更新**：2026-10-30

## 0. 怎么用这份文档

1. 先看第 1 节确认现状（数字会随时间失效，动手前重新实测一次）。
2. 第 3 节是各系统设计，每条都标了「作用于哪个文件」。
3. 第 6 节是实施顺序，**顺序本身是设计的一部分**，尤其第 ① 步不可调整。
4. 第 7 节「明确不做」和正文同样重要——它们是防滑坡的护栏。

## 2. 三条护栏

这三条是硬约束，任何设计不得违反。

### 护栏 A · 可选内容不得卡住任何进度

- 不打守夜，必须能 100% 通关。
- 守夜产物只能是**装饰性 / 社交性**（灯芯纹样、猫玩具、NPC 好感、图鉴），**绝不出产修灯必需材料**。
- 反之亦然：不种地也必须能推进到底（见 3.1 有损兑换）。

### 护栏 B · 战斗零写入经营状态

- 守夜只读 `garden_state`，不得扣真实露滴 / 毁作物 / 推进时间。
- 战斗参数用「镜像」方式复制，天亮丢弃。
- 失败 = 灯熄回白天，不是角色死亡、不是进度回退。

### 护栏 C · 永不做不可逆的选择

- 灯谱免费重置。
- 融合失败不销毁材料。
- 传送不可达「未亲自走过」的地点（永久的铁律）。

## 3. 系统设计

### 3.1 双轨经济（农牧 / 守夜 / 双修）

玩家的玩法偏好由**行为隐式决定**，不做开局门派选择。

| | 农牧专精 | 守夜专精 | 双修 |
| --- | --- | --- | --- |
| 主收入 | 露滴 + 灯孢 | **夜露**（战斗专属） | 混合 |
| 战力来源 | 灯芯强化光域（78→86→94） | 夜露购买夜灯 / 战斗器具 | 两条都有但都慢半拍（补偿见 3.20） |
| 修灯成本 | 6 灯孢 + 4 露滴 | **折合 20 夜露** | 混合 |
| 世界进度 | 共享（灯 / 区域 / 灯路） | 共享 | 共享 |
| 目标时长 | **1.00x** | **1.30x** | **1.15x** |

**规则**：

1. **有损兑换**：夜露 : 灯孢 = **2 : 1**。无损兑换 = 两条路等价 = 选择失去意义；有损 = 专精有回报、混合有弹性，但**没有任何一条会卡死**。
2. **世界进度只有一套**。分叉的是"怎么变强"，不是"能去哪"。不做两套地图、两套进度。
3. **隐式分流**：记录 `nights_survived` 与 `total_harvests`（`garden_state.gd:32` 已存在），约 20 分钟后按比例倾斜收益倾向，**随时可变**。

**死锁检查清单（每次改动后必过）**：

- [ ] 纯守夜能修灯（靠夜露 20:1 折合）
- [ ] 纯农牧能打最难一夜（靠灯芯 + 遮蔽物）
- [ ] 没有区域只允许一条路线进入
- [ ] 最难一夜不要求战斗产物
- [ ] 任一货币都不能单独卡死进度

### 3.3 融合系统：属性层 + 手感层

> ⚠️ **v16 定位变更**：融合产物**不再是手持道具，而是「兵器附痕」**——在灯匠处配到兵器的痕槽上，用 8 次就碎（见 **3.7.12**）。
> 下表的**名字与效果全部沿用**，只是"载体"从"手里拿的东西"变成"系在兵器上的一道痕"。
> 原因：道具和兵器抢同一个 `E` 键，会让玩家在"用兵器"和"用道具"之间做一次不该做的选择。

**核心决定：融合的是属性，不是道具。**

道具可以有几十个，属性只有 4 个，结果空间被锁死，不会爆炸。

| 属性 | 载体 |
| --- | --- |
| 阴（影） | 月苔 |
| 阳（光） | 灯铃 / 灯芯 |
| 润（水） | 露滴 |
| 燃（火 / 暖） | 提灯 / 苔灯灯室 |

4 属性 → **10 个结果**（4 自融 + 6 对融）。

### 3.4 搭配：2 槽 × 5 + 5 = 25 组合

| 方案 | 组合数 | 判断 |
| --- | --- | --- |
| 2 自由槽 × 8 件 | 36 | 偏多 |
| 2 自由槽 × 10 件 | 55 | ❌ 设计不完，必然出现废件 |
| **2 槽，各装一类（光类 5 / 苔类 5）** | **25** | ✅ 采纳 |

**槽位分类制造搭配**：玩家必须跨类型思考，而不是"把两个最强的塞进去"。

**跨轨搭配是灵魂**：

| 搭配 | 效果 |
| --- | --- |
| 夜灯（战斗侧）+ 深影囊（经营侧） | **能在夜里种月苔** |
| 提灯 + 雾 | 雾里只有脚下是亮的 → 隐蔽且能种 |
| 光引 + 苔钩 | 远程拉亮再远程收成 |

因为融合改变的是**动词手感**，所以：**25 种搭配 = 25 种操作体验组合**，而不只是 25 组数值。

### 3.5 灯谱（技能树）

> 早期结论是"不做技能树"，理由是内容量撑不起。**该前提已失效**（现有：双货币、25 搭配、5 区域 5 机制）。详见第 8 节决策 #2。

**形态**：3 层 × 4 节点 = **12 个节点封顶**，全部落在一个屏幕内。

#### 12 个节点（v2 定稿）

| id | 层 | 名称 | 效果参数 | 作用面 |
| --- | --- | --- | --- | --- |
| `grass_step` | L1 | 穿草 | 冲刺可穿草丛 / 矮栅栏（切换 `collision_mask`） | 碰撞分层（3.7.6） |
| `dew_thrift` | L1 | 省露 | 每第 3 次促长不耗露滴 | 资源 |
| `wide_reach` | L1 | 广收 | 交互半径 20 → 28 | `farm.gd:10` |
| `quick_bed` | L1 | 速播 | 播种 `startup` 0.15 → 0.08 | `feel.json` |
| `hand_lantern` | L2 | 手提灯 | 插地成临时光源 30 秒 | `lanterns` 加 temp 项 |
| `borrow_light` | L2 | 借光 | 灯路传送本体（需 `restored>=2`） | 3.6 |
| `deep_pocket` | L2 | 幽囊 | 深影囊携带 1 → 2 | 3.3 |
| `mist_trail` | L2 | 雾尾 | 冲刺雾带 2 → 3 秒 | `feel.json` |
| `light_thrift` | L3 | 省灯 | 借光量减半 | 3.6 |
| `lamp_bearer` | L3 | 提灯远行 | 可携带一盏灯做移动传送点（**不可在未探索区落地**） | 3.6 + 护栏 C |
| `mist_step` | L3 | 雾步 | 冲刺穿过雾带时不减速（`speed_mult` 0.8 → 1.0） | `feel.json` |
| `night_eye` | L3 | 夜枭之眼 | 雾浓度惩罚 −20% | 守夜难度 |

#### 点数经济（不引入新货币）

| 项 | 规则 |
| --- | --- |
| L1 四个节点 | 修复第 1 盏灯时**免费全开**（不占点数） |
| L2 / L3 各节点 | 每点 1 |
| 点数来源 | 每修复一盏灯 **2 点**（共 6）+ 每区首次通关 **1 点**（共 5）= **11 点** |
| 需求量 | 8 点即可全解锁 → 余 3 点属于**解锁顺序的选择**，不是稀缺资源 |
| 重置 | 灯匠处免费重置（护栏 C） |

**为什么给 11 点但只需 8 点**：让玩家有 3 点的顺序选择空间，但永远不出现"点数不够所以卡住"。稀缺会造成焦虑，顺序选择才有意思。

#### 3.5.1 解锁途径：四途径 + 冗余原则（v5 新增）

**灯谱节点不是只有"点数"一条路。** 四途径覆盖四种玩家动机：

| 途径 | 载体 | 例子 | 与「无人派任务」是否冲突 |
| --- | --- | --- | --- |
| **① 点数** | 修灯 2 点 / 每区首次通关 1 点 | L1 四个节点 | 无 |
| **② 世界收集** | 地图上的可拾取物（刻字石碎片、旧工具） | 捡到 4 块导光苔枝碎片 → `borrow_light` | **无**——物件不会派人 |
| **③ 世界装置** | 需要条件的实体装置（石匣、封着的门） | 灯路谷石匣需导光才开 → `lamp_bearer` | **无** |
| **④ NPC 一句话** | 对话里的一次性请求（**不进菜单**） | 灯匠："给我 3 个暖铃，我教你怎么把灯带走。" → `hand_lantern` | **不冲突**——因为它不进任务日志 |

##### ⭐ 冗余原则（硬规则）

> **每个节点至少 2 条解锁途径，且其中一条不需要任何操作技巧。**

原因：四途径一引入，最大的风险是「某个节点只有一条打怪路线」，那条路线就变成了强制战斗。冗余原则是护栏 A 在解锁层的落地。

| 节点 | 主途径（有趣） | 备途径（不需要技巧） |
| --- | --- | --- |
| `hand_lantern` | 灯匠的请求 | 点数 1 |
| `borrow_light` | 收集 4 块导光苔枝碎片 | 点数 1 |
| `deep_pocket` | 世界装置：池底石匣 | 点数 1 |
| `mist_trail` | 收集 3 片雾羽 | 点数 1 |
| `lamp_bearer` | 灯路谷石匣 | 点数 1 |
| `night_eye` | 夜行旅人的一句话 | 点数 1 |
| …（其余同理） | | **每个节点都有"点数兜底"** |

##### 明确不做（解锁层）

- ❌ 任务清单 / 任务日志 / 进度追踪 / 打勾列表
- ❌ 限时任务（会破坏"随时离开"的舒适感）
- ❌ **把 NPC 好感当解锁门槛**（好感只给情感，3.10）
- ❌ 「已解锁 7/12」这种进度条（改成手账里的"看见"而非"计数"）

> **判断标准**：玩家应该感觉自己在**发现**东西，而不是在**完成**清单。

#### 四条硬规则（复核用）

1. **浅而宽**：不做深度树（深度 = 必刷 = 疲劳）。
2. **无不可逆**：灯匠处免费重置。
3. **节点必须落得到 `feel.json` 的字段上**。能写成 `{"kinematics":{"startup":0.08}}` 的才是节点；写成 "+5% 光照" 的不是。
4. **不锁核心动词**：走 / 冲 / 格挡 / `E` 永不上树。树上只放修饰与变体。
5. **华丽层不进树**：连招、完美闪避、完美格挡、派生**不占点数**（3.7.8）。它们属于操作层的自发现，一旦进树就变成"必须点"，会同时伤到高玩（被卡）和手残（觉得是必修）。

UI：并入手账页，**零新美术**。

### 3.6 借光传送

> **传送 = 从目标灯里借走一段光。灯会变暗，光域缩小，约 20 秒自然回充。**

**为什么用灯火而不是露滴**：修一盏灯要 4 露滴（`garden_state.gd:22`），用露滴做传送费就是跟"修灯必需材料"抢预算。灯火消耗零新货币、代价可见、且天然限流。

**前置条件（全部是现成字段）**：

- 目标灯 `restored && lit`（`is_lit():83` 已有判定）
- `get_restored_count() >= 2` 才有灯路可借（`:210`）
- 修复 3 盏后灯路连通 → 借光量减半（`:169` 已有提示文案）

**状态消耗规格**：

| 参数 | 值 |
| --- | --- |
| 每次借光 | 目标灯「灯芯」扣 100%（或按距离以外的固定量） |
| 自然回充 | 20 秒 |
| 蓄力时间 | 2 秒原地不动（不能边跑边传） |
| 灯暗期间 | 光域缓慢收缩 → 该区域灯铃停止生长（`growth_condition():90`），月苔恢复生长 |
| 禁止场景 | **战斗中不可用** |
| 付费加速 | **不做**（一做就变成"花钱偷懒"） |

**「小地图也不能偷懒」的解法：用算术，不用规则。**

借光消耗**与距离无关**。当前地图横穿只要 10.9 秒，所以任何传送都不划算——玩家自己就不用了。**不写一行限制代码。**

> 短途走路 5 秒 vs 蓄力 2 秒 + 灯变暗 20 秒 → 玩家一算就懂。

**风险护栏**：

- 灯变暗必须**缓慢过渡** + 给「灯芯恢复中」提示，不能"啪"一下灭掉
- 不可达未亲自走过的区域（护栏 C）

**平衡验收指标**：

| 指标 | 目标 |
| --- | --- |
| 传送使用频率 | < 每 3 分钟 1 次 |
| 短途（< 2 屏）传送占比 | < 10% |
| 因传送导致作物停长的时长占比 | < 5% |
| 修复 2 盏前尝试传送次数 | 0（提示"灯路未成"） |

### 3.7 动作层：位移 · 门控 · 闪避 · 格挡 · 连招

#### 3.7.1 动词表（v3 收敛：5 个名字 → 4 个动词）

| 动词 | 键 | 覆盖的旧概念 |
| --- | --- | --- |
| 走 | `WASD` | 走路 |
| **冲刺** | `Shift` | **冲刺 + 奔跑 + 加速 + 翻滚 + 瞬移，五合一** |
| **格挡** | 右键 / `K` | 新增（战斗专用） |
| 使用 / 交互 | `E` | 原有 |

**为什么删掉独立翻滚**：实测位移量只差半个格子——

| 动作 | 参数 | 位移 |
| --- | --- | --- |
| 冲刺 | 0.18s × 317px/s | 57px（3.6 格） |
| 翻滚 | 0.35s × 141px/s | 49px（3.1 格） |
| 差 | — | **8px = 0.5 格** |

而窄缝只有 1~2 格宽，两者的移动距离都远超需求。更关键的是：**"翻滚"存在的唯一理由——时间无敌——已经改为空间判定（3.7.4）**，所以它没有独立功能。冲刺结束时站在阴影格就是闪避；冲刺穿过窄缝就是钻缝。**一个键全包。**

#### 3.7.2 地形门控（环境许可替代能力许可）

冲刺**一开始就会**，但地图上最初没有缝。

| 动作 | 门控地形 | 经营用途（这才是重点） |
| --- | --- | --- |
| 冲刺 | 可穿矮栅栏 / 草丛 | 抢生长窗口（18s / 24s） |
| 冲刺 | 可钻 **1 格窄缝** | ⭐ 进入原本进不去的深影洞穴种月苔 |
| 跃（可选） | 可上台地 | 立体苗床：光照从"平面距离"变成"高度差" |

**差别**：能力许可 = "你等级不够"（被剥夺感）；环境许可 = "这里有缝，我钻进去试试"（聪明感）。对 comfort game，后者几乎是唯一正确解。

#### 3.7.3 操作衔接：三件事 + 一条限制

| 类型 | 例子 | 采纳 |
| --- | --- | --- |
| 动量衔接 | 冲刺结束保留 40% 速度 0.15s | ✅ |
| 输入缓冲 | 落地 / 受击前 **120ms** 按任一动作也算成功 | ✅ |
| 取消窗口 | 冲刺后 150ms 内可**再次冲刺**（仅 1 次） | ✅ 限 1 次 |
| 连段派生 | 见 3.7.8（**仅战斗内**） | ✅ 3 招 × 2 段 |

**原则**：衔接是"让玩家更顺"，不是"让玩家更强"。

#### 3.7.4 闪避与格挡：三层结构（地板 + 天花板）

**这是全部"操作上限"设计的总纲。** 判断标准只有一句：

> **精通只改变"你多快打完 / 多帅"，永不改变"你能不能打完"。**

| 层 | 触发 | 结果 | 门槛 |
| --- | --- | --- | --- |
| **① 基础脱战**（地板） | 冲刺结束时位于阴影 / 雾中（`garden_state.gd:80` 现成） | 敌人**失去目标** 2s，转向别处 | 空间判定，人人可读 |
| **② 完美闪避**（天花板） | 敌人「预备帧」最后 **0.15s** 内冲进阴影 | 敌人**光眩 1.5s** + 冻帧 + 反相白闪 + 镜像露滴 +1 | 时间窗，靠观察 |
| **③ 完美格挡**（天花板） | 敌人吸食判定到达的**同一帧**举起灯 | 敌人被反震光眩 2s + 冻帧 + 三音下行 | 时间窗，靠练习 |

**必须注意**：①**不能是无敌**，只能是"脱战"。如果地板层也无敌，时间窗就只是在重复空间判定，等于白做。这个区分是整块设计成立的关键。

#### 3.7.5 完美格挡：挡的不是攻击，是「你在护的东西」

这是本项目格挡设计的关键决策。

**问题**：敌人**不攻击玩家本体**（角色没有 HP，护栏 B）。所以"格挡"没有传统的对象。

**解法**：把格挡对象定义为**你正在保护的东西**——

| 格挡的对象 | 场景 |
| --- | --- |
| 手提灯里的灯火 | 雾蛾扑向灯时举灯挡住吸食 |
| 场上的深影囊 / 雾带 | 光噬吞噬遮蔽物时用身体挡在前面 |
| 灯本身 | 光噬贴到苔灯前的那一瞬 |

> **这正是"巡灯人"的身份**：你不是战士，你护的是光，不是自己。

**这个决策带来三个好处**：
1. 不需要给角色加 HP，护栏 B 完好无损。
2. 格挡失败没有"被扣血"的挫败——只是没护住（镜像值损失，天亮退还）。
3. 和主题完全自洽，不是硬塞进来的动作游戏机制。

#### 3.7.6 技术前置：`player.gd` 重构

`player.gd:13-14` 现在是直接赋值，没有状态机、没有缓冲、没有帧数据：

```gdscript
velocity = direction * move_speed
```

必须重构到 **~450 行**（v2 估 300，加入格挡与连招后上调）：

```
ActionState { idle, move, dash, block, strike, interact }
+ 输入缓冲（120ms）
+ 帧数据表（由 feel.json 驱动）
+ 动量继承参数
+ 连招队列（3 招 × 2 段，窗口 400ms）
```

**这是全项目唯一必须提前做的基础重构**，`feel.json` 的 `kinematics` 字段全靠它。

#### 3.7.7 冲刺参数定稿（v3）

**关键区分**：`startup`（按下到开始动）与 `duration`（动作时长）是两码事。

| 档 | startup | duration | speed | 距离 | 占光域 R=78px | 评价 |
| --- | --- | --- | --- | --- | --- | --- |
| v2 旧值 | 0.18s | 0.18s | 317（3.6x） | 57px（3.6 格） | 73% | 起手偏肉 |
| **点按（基准）** | **0.06s** | 0.18s | **396（4.5x）** | **71px（4.4 格）** | **91%** | ✅ 采纳 |
| **长按蓄力** | 0.06s | 0.32s | 396 | 126px（7.9 格） | 162% | 可选，需蓄力 0.3s |
| 危险区 | 0.06s | 0.25s | 528（6x） | 132px（8.2 格） | 169% | ❌ 屏高 36.7%，画面会晃 |

**两条硬约束决定了上限**：

1. **光域半径 R = 78px 是唯一核心度量**（`garden_state.gd:18`）。冲刺超过 R 就"一冲脱离光域"，"位置 = 光照条件"这条设计就失去意义。→ 点按基准封顶 **0.9R**。
2. **视口只有 640×360，且 `player.tscn` 里 `position_smoothing_enabled = false`**。132px 的位移 = **屏高 36.7%**，相机无平滑 → 每次冲刺画面都跳。

**配套修复（成本 S，两行）**：冲刺期间临时启用相机平滑（`position_smoothing_speed ≈ 8`），结束后恢复 `false` 以保持像素级精确对齐。

> **真要更远**：不给全局数值，改成**长按蓄力两档**（点按 4.4 格 / 长按 7.9 格）。取舍留在玩家手上，符合"衔接让玩家更顺"的原则。

#### 3.7.8 华丽层：连招与派生（v3 新增）

##### 规模锁：3 招 × 2 段 = 12 节点

| 方案 | 需设计的分支数 | 判断 |
| --- | --- | --- |
| **3 招 × 2 段** | **12** | ✅ 采纳 |
| 3 招 × 3 段 | 39 | 偏多 |
| 4 招 × 3 段 | **84** | ❌ 每支都要一套特效/音效/帧数据，不可能 |

**3 招**：横扫（`E`）/ 突进（`Shift`）/ 举灯格挡（右键）。**2 段**：单招 + 6 个二段组合 + 3 个收尾 = 12 个节点。

##### ⭐ 派生靠「情境触发」，不靠「背输入表」

这是让"华丽"和"不为难手残"共存的关键设计：

| 派生 | 触发条件（**不是**按键顺序） | 效果 |
| --- | --- | --- |
| **穿灯** | 突进结束时敌人正处于光眩 | 直接穿透，敌人熄灭 3s |
| **反震** | 格挡成功后的 0.4s 内横扫 | 溅射伤害，波及 ±2 格 |
| **灯潮** | 连续 3 次冲刺结束都站在阴影里 | 临时光域 +30%，持续 5s |

玩家学到的是**规则**（"敌人晕了就能穿"），不是**序列**（"按 A→A→B→C"）。会玩的人看起来像在打连招，实际上是读懂了敌人的状态。**这就是"华丽"和"背表"的分界线。**

##### 输入窗口：宽到不欺负人

| 窗口 | 时长 | 出处 |
| --- | --- | --- |
| 格斗游戏连段 | 8 帧 = 133ms | 硬核，**不采用** |
| 动作游戏平均 | 16 帧 = 267ms | 偏紧 |
| **本作标准** | **24 帧 = 400ms** | ✅ 采纳 |
| 过于宽松 | 30 帧 = 500ms | 会失去节奏感 |

**400ms 是普通玩家的反应时间区间**，配合 120ms 输入缓冲，连招在体感上接近"想按就能按出来"。

##### 华丽感从哪来：**不是招式数量**

> **华丽感 ≈ 特效层次 × 音效层次 × 意外感。招式数量的贡献很小。**

玩家记住的是"那一下白光 + 嗡鸣"，不是"我按对了 4 个键"。所以：

| 方案 | 成本 | 华丽感 |
| --- | --- | --- |
| 3 招 × 每招 3 层反馈 | 基准 | ★★★★ |
| 8 招 × 每招 1 层反馈 | **2.7 倍** | ★★☆ |

**结论：宁可 3 招做透，不要 8 招做浅。**

##### 华丽层**不进灯谱**

连招、格挡、派生**不占灯谱点数**。理由：一旦进了树，就变成"必须点"，否则高玩会觉得被卡；而点了又会让手残玩家觉得"这是必修"。**它应该纯粹是操作层的自发现，不是进度条。**

#### 3.7.9 键位职责表（v3 新增）

现有 `project.godot` 已有 **12 个 input action**，且**没有任何 dash / shift 绑定**。文档又叠了"两个搭配槽"的需求，而 `1 / 2` 已被种子占用。所以一次重排，**零新键**：

| 键 | 职能 | 规则 | 鼠标 | 手柄 |
| --- | --- | --- | --- | --- |
| `WASD` | 走 | 唯一持续位移 | 左键点地面 = **短距直走**（不寻路，见 3.15.1） | 左摇杆 |
| **`Shift`** | 冲刺 | 唯一瞬时位移；承载穿越 / 闪避 / 放雾 / 连招第 2 段 | `Shift` 或 **双击左键地面方向** | `RB` |
| **`K`** | 格挡 | 战斗专用，非战斗时无响应 | **右键按下** = 格挡 | `LT` |
| `1` `2` | 手：月苔 / 灯铃 | 播种用 | **滚轮**在 1~4 之间循环 | `十字键 左右` |
| `3` `4` | 手：融合道具 A / B | 对应 2 槽搭配 | 同上 | 同上 |
| `E` | 使用手持 / 交互 | **上下文：有可交互目标时优先交互**；战斗中为横扫 | **左键点物件** = 直接对其交互 | `A` |
| `Q` `R` | 促长 / 移除 | 只对苗床有效 | `Q`/`R` 或 **Alt+左键** = 移除 | `LB` / `Y` |
| `Tab` `M` `Esc` `F11` | 界面 | 不动 | 手账页签可点 | `Back` / `Start` |

一句话：**`1-4` 管"手里拿什么"，`E` 管"用出去"，`Shift` 管"怎么动"，右键管"怎么护"。**

> **v15 补充**：`E` 用什么，由**两层**决定——**元素**（`1-4` 槽的光尘，决定 4 把兵器里的哪一族）+ **器形**（手账里选定这一族里的哪一把）。**换元素 = 换整套兵器；换器形 = 换族内手感。零新键**（3.7.11 ⑤）。

##### 鼠标操作的三条规则（v12 新增）

| 规则 | 内容 |
| --- | --- |
| **左键点地面 ≠ 寻路** | 只朝该方向走一小段（≤3 格）就停，**不做 AI 寻路**（3.15.1 明令禁止）。它就是"用鼠标代替 WASD"。 |
| **左键点物件 = 走过去并交互** | 若物件在 `INTERACTION_RADIUS`（20px，`farm.gd:10`）内则直接交互；否则只走一段，第二下再交互。**不自动绕路**。 |
| **灯下模式全靠鼠标** | 陪伴模式的 6 种交互（3.17.6）本来就是点物件，**鼠标是它的首选输入** |

##### 手柄的两条规则（v12 采纳 D1）

| 规则 | 内容 |
| --- | --- |
| **灯下 / 交互自动吸附** | 自动选中最近的物件 + 高亮，`十字键`切换目标，**不做光标**（D1） |

#### 3.7.10 碰撞分层（必须先做）

`farm.gd:151-161` 的 `_add_collision` 把 `collision_layer` 写死为 1，所有几何都在同一层。**"矮栅栏能冲过去、围墙不能"现在根本无法表达。**

改造：`_add_collision(rect, name, layer)` 加参数，拆出「可穿透层」与「实体层」，dash 期间切换 player 的 mask。`player.tscn` 目前 `collision_layer=2 / collision_mask=1`。

**不做这一步，所有"穿"的设计都落不了地。**

#### 3.7.11 「引」：四元素 × 四器形（v15 重写）

> 主人的要求：保留「引」，**每个元素要有自己的武器**，不要都用长剑大剑；请参考真实近远程兵器。
>
> **查证后的两个关键依据**（`zh.wikipedia.org/wiki/冷兵器`、`gamedesign.gg/articles/weapon-design`）：
> ① 冷兵器的**传统分类本身就横跨兵器与农具**——「长柄：矛枪戈戟」「短柄：剑刀匕首」「远射：弓弩投石索镖」「系兵器：飞爪绳镖锁镰」「农具：叉耙犁锄斧」。
> ② 武器设计的硬标准：**每把武器必须有"别的武器做不了的动作"**；「两把武器共享一个动作，就砍掉弱的那个」；**有效距离带之间不允许包含关系**（否则强的那把直接杀死弱的那把）。

##### ① 设计语言：一元素 = 一个兵器家族

| 元素 | 家族 | 传统依据 | 共同气质 |
| --- | --- | --- | --- |
| **阴** | **暗器系** | 短柄＋系兵器（匕首 / 飞爪 / 绳镖 / 吹箭） | 短、藏、收 |
| **燃** | **破坏系** | 钝器＋抛掷＋火（斧 / 锤 / 投石索 / 火把） | 钝、重、燃 |
| **阳** | **长兵系** | 长柄＋射远（枪 / 杖 / 弓 / 戈） | 直、远、正 |
| **润** | **软兵系** | 软兵器＋农具（鞭 / 连枷 / 网 / 镰） | 缠、绕、罩 |

> **这四个家族不是硬凑的**——它们各自对应真实兵器谱里一整类，而且**每一件在真实世界里本来就是农具**（维基「其它：常用于生产领域的传统农具」那条）。所以"战斗侧与种植侧共用一把"不是设计妥协，是**本来就是同一件东西**。

##### ② 十六把，每把一个独占动作

**阴 · 暗器系**（短、藏、收）

| 器形 | 独占动作 | 战斗 | 种植 |
| --- | --- | --- | --- |
| **匕** | **刺** | 贴身最快（0.05s），命中即入阴影判定 | 点种 / 点收单格（最准） |
| **飞爪** | **抓** | 把远处敌人**拉过来**（唯一拉人的兵器） | 抓高枝、抓回漂走的苗床 |
| **绳镖** | **收** | 投出后再拉回，**往返两次判定** | 够到远处收一株 |
| **吹箭** | **暗** | 极远、无声、单体必暴，但装填最慢（0.6s） | 打落高处果子 |

**燃 · 破坏系**（钝、重、燃）

| 器形 | 独占动作 | 战斗 | 种植 |
| --- | --- | --- | --- |
| **斧** | **劈** | 直线碎击，**唯一能直接破坏遮蔽物** | 劈柴、砍倒一整丛 |
| **锤** | **砸** | 击退 + **无视格挡** | 砸开石壳、砸实松土 |
| **投石索** | **抛** | 旋转蓄力 0.4s，**落点范围伤害** | 打落成片果子 |
| **火把** | **燃** | 点燃、逼退、照亮一小片 | 熏虫、烤（催熟一格） |

**阳 · 长兵系**（直、远、正）

| 器形 | 独占动作 | 战斗 | 种植 |
| --- | --- | --- | --- |
| **枪** | **突** | 最长直线（5 格），**可穿透一格** | 挑高处的果子 |
| **杖** | **架** | 横扫 + **可当格挡用**（唯一攻防一体） | 打落树枝 |
| **弓** | **射** | 远程直线，需站定 0.3s | 射落高处 |
| **戈** | **钩** | 勾住敌人**拉近但不拉到自己身上** | 钩下枝条 |

**润 · 软兵系**（缠、绕、罩）

| 器形 | 独占动作 | 战斗 | 种植 |
| --- | --- | --- | --- |
| **鞭** | **扫** | 长弧横扫，**多目标** | 扫过一整片 |
| **连枷** | **绕** | **绕过格挡与障碍** | 绕过石墙浇水 |
| **网** | **罩** | **罩住但不伤害**（唯一纯控制） | 罩住防虫、遮光造影 |
| **镰** | **割** | 勾割，范围收割 | 割一片（最经典的农具动作） |

##### ③ 独占性自检（按设计标准逐条查）

| 动作 | 唯一拥有者 | 会不会和别的重复 |
| --- | --- | --- |
| 刺 | 匕 | 突（枪）是长直线，刺是贴脸——不重复 |
| 抓 | 飞爪 | 唯一"把东西拉向自己" |
| 收 | 绳镖 | 唯一"往返两次判定" |
| 暗 | 吹箭 | 唯一"无声+必暴+慢装填" |
| 劈 | 斧 | 唯一"破坏遮蔽物" |
| 砸 | 锤 | 唯一"无视格挡" |
| 抛 | 投石索 | 唯一"范围落点" |
| 燃 | 火把 | 唯一"持续点燃" |
| 突 | 枪 | 唯一"穿透" |
| 架 | 杖 | 唯一"攻防一体" |
| 射 | 弓 | 唯一"需要站定" |
| 钩 | 戈 | 唯一"拉近但不贴身" |
| 扫 | 鞭 | 唯一"长弧多目标" |
| 绕 | 连枷 | 唯一"绕过障碍" |
| 罩 | 网 | 唯一"不伤害" |
| 割 | 镰 | 唯一"贴地范围收割" |

> **16 个动作，0 个重复。** 这是按"两把武器共享动作就砍掉弱的"这条标准逐条查过的结果。

##### ④ 距离带互不包含（第二条设计标准）

```
贴脸 ── 匕·刺 ── 锤·砸 ── 镰·割 ── 杖·架 ── 枪·突 ── 鞭·扫 ── 弓·射 ── 吹箭·暗
 1格        2格       2格      2~3格    3格      3~5格    4格      5格       5~6格
```

（另有飞爪/戈/绳镖是**变距**兵器——它们的作用是"改变距离"，所以不在固定带上）

> 没有一条带完全包含另一条。**所以没有"上位替代"，每把都有它赢的那一格。**

##### ⑤ 怎么选？元素决定家族，手账决定这一族里的哪把

```
光尘（1-4 槽）→ 决定元素 → 决定家族（4 把）
手账「引」页 → 在家族里选一把（记在心中，长期不变）
对着目标按 E → 用那一把
```

- **换元素 = 换整个家族**（阴尘 ↔ 燃尘 就是完全两套兵器）
- **换器形 = 换家族内部的手感**（鞭 ↔ 网 都是润，但一个打一个控）
- **零新键**

##### ⑥ 素引：一根灯杆

| 状态 | 能力 |
| --- | --- |
| 无光尘 | 只有一根**灯杆**：一个动作「拨」（打一下、拨一下苗） |
| 有光尘 | 该元素家族 4 把全部可用 |

> **梯度对了**：素引是"手里有灯"，有光尘才是"手里有兵器"。

##### ⑦ 两群玩家的入口（这次更分明了）

| | 休闲玩家 | 战斗玩家 |
| --- | --- | --- |
| 元素 | 阴（割暗处）/ 燃（割亮处） | 四种轮换 |
| 器形 | 镰 / 斧 各一把，够用 | 每种元素 4 把都试 |
| 需要掌握 | **2 把**（镰割、斧劈） | 16 把（可分批摸） |
| 深度来源 | 种什么、摆哪、季节 | 16 把的独占动作 + 连招派生 + 完美闪避 |
| 被迫接触对方 | ❌ | ❌ |

> **休闲玩家用到的"镰"和战斗玩家的"镰"是同一把**——只是他永远不用去想另外 15 把。**同一条规则，两个入口。**

##### ⑧ 诚实成本：16 器形，但只有 8 种笔法

| 项 | 数量 | 说明 |
| --- | --- | --- |
| 器形 | **16** | 每元素 4 把，动作各不同 |
| **轨迹笔法** | **8 种** | 直线突 / 弧砍 / 圆扫 / 折钩 / 抛物 / 扇面 / 网状 / 螺旋——**多数器形是笔法的不同比例与时长** |
| 颜色 | 4 + 1（素） | 参数 |
| 音效 | 16 个 cue | 但只 8 种基色，元素改 `pitch` |

> **比 v14 的"4 套"贵一倍，但比"16 套独立美术"省一半。** 这是 16 把兵器能落地的真实价位。

##### ⑨ 与既有系统的衔接

| 系统 | 影响 |
| --- | --- |
| **3.7.8 连招（3 招 × 2 段）** | 不变。器形只改「`E` 那一招」；派生仍靠敌人状态 |
| **3.7.4 三层闪避** | 不变。匕的"命中即入阴影"让阴系天然好接闪避 |
| **3.3 融合（10 配方）** | 不变。融合物是独立道具，与器形共用 `E`，靠"手持什么"区分 |
| **3.20 双修补偿** | 形态免费切换，双修不必为两族各练一遍 |
| **3.7.9 键位** | 不变，仍零新键 |

##### ⑩ 四条硬规则

1. **每把必须有独占动作**——两把共享动作就砍掉弱的（设计标准 ①）
2. **距离带互不包含**——不允许上位替代（设计标准 ②）
3. **不出数值强弱**——16 把的秒伤大致相等，强弱来自动作，不来自数字
4. **每元素恰好 4 把**——第五把必然和现有四把之一抢动作

#### 3.7.12 「附痕」：融合与兵器的唯一接口（v16 新增）

> 主人问：有了 16 把兵器之后，**元素之间的融合该怎么创造特色与可玩点**？
>
> **答案：融合不再"造道具"，而是"往兵器上系一道痕"。**

##### ① 先修一个隐患：融合产物原来和兵器抢同一个键

v15 之前，融合产物是「手持道具」，和兵器共用 `E`，靠"手里拿什么"区分。问题是：**玩家要在"用兵器"和"用道具"之间做一次选择——而那不该是一个选择，因为它是同一件事。**

**改成附痕之后，`E` 永远只做一件事：引。** 痕不占按键，它只改写"引完之后地上留下什么"。

##### ② 三层结构：动作 × 性质 × 后果

| 层 | 是什么 | 决定 | 谁在改 | 占按键吗 |
| --- | --- | --- | --- | --- |
| **兵器** | 16 把，分 4 族 | **动作**（刺/劈/突/割…） | 手账里选 | 否（`E`） |
| **元素** | 阴/燃/阳/润（光尘） | **性质**（颜色 / 明暗 / 附效） | `1-4` 槽 | 否（`1-4` 已有） |
| **痕** | 10 种，由融合合成 | **后果**（这一击在地上留下什么） | 灯匠处配 | 否（配装，不战斗中换） |

> **三层各管一件事，互不抢键。** 这是这一版最重要的结构改动。

##### ③ 痕的规则

| 项 | 规格 |
| --- | --- |
| 槽位 | 每把兵器 **1 个痕槽**（不是 2 个——2 个会变成组合爆炸） |
| 来源 | 融合（任意两属性合成一份痕，见 3.3 的 10 配方） |
| 耐久 | **8 次命中**，或换季即失效 |
| 重做 | 回灯匠处，用材料重配（**每日一次出门前的仪式**） |
| ⭐ **同源加成** | 痕属性 **=** 兵器元素 → **完整效果**；**≠** → **效果减半**（"勉强"） |
| 不产数值 | 痕只改**判定与光场**，不加伤害数字（特效即信息，3.3） |

**同源/异源这一条是搭配深度的全部来源**：

```
16 兵器 × 10 痕 = 160 组合，但玩家只需要懂一件事：
「我这把是阴的，配阴痕才顺手。」
```

##### ④ 十个痕（把原 10 配方从"道具"改成"判定改写"）

**同源四种（强化本元素的后果）**

| 配方 | 痕 | 效果（同源完整 / 异源减半） |
| --- | --- | --- |
| 阴+阴 | **影囊痕** | 每击在原地留 **1 格深影，8 秒** |
| 燃+燃 | **灯芯痕** | 每击**点燃**命中格，3 秒，照出一小片暖光 |
| 阳+阳 | **引线痕** | 每击沿直线**延长 2 格光**，6 秒 |
| 润+润 | **露痕** | 每击在该格挂一颗露，**采一下得 1 露滴** |

**对融六种（把两种性质叠在一格上）**

| 配方 | 痕 | 效果 | 为什么重要 |
| --- | --- | --- | --- |
| 阴+润 | **苔痕** | 命中格变**湿阴影**：可种月苔，且 +20% | ⭐ 打一条地 = 造一条月苔苗床 |
| 阳+燃 | **暖痕** | 命中格变**干暖光**：可种灯铃，且 +20% | ⭐ 打一条地 = 造一条灯铃苗床 |
| 阴+阳 | **二向痕** | 命中格**阴阳并存**（既是深影又是暖光） | ⭐⭐ **这就是星铃的双光条件** |
| 阳+润 | **光雨痕** | 命中格同时被**照亮 + 浇灌** | 一晚把荒地变成能种的地方 |
| 润+燃 | **雾痕** | 每击散 1 格雾（光强 ×0.5，20 秒） | 战斗中造遮蔽，田里造深影 |
| 阴+燃 | **影烛痕** | 命中格**暗但烫**：暗处也带灼烧 | 唯一"暗属性也能输出"的痕 |

##### ⑤ ⭐ 这一版最强的一点：**打一场 = 画一幅可以种的图**

把上面六条连起来看：

```
苔痕   → 地上长出湿阴影 → 种月苔
暖痕   → 地上留下暖光   → 种灯铃
二向痕 → 同格阴阳并存   → 种星铃（它需要双光叠加）
光雨痕 → 照亮 + 浇灌    → 把荒地变成可种地
```

**于是"战斗"第一次真的在"生产耕地"，而不是消耗资源。**

而且它解释了为什么这几把兵器值得练：
- 拿「镰 + 苔痕」在月苔灯圃扫一遍 → 得到一片新苗床
- 拿「弓 + 二向痕」在远处射几箭 → 得到一小片星铃地
- 拿「网 + 光雨痕」罩住一片 → 一夜之间荒地变良田

##### ⑥ 组合数：160 → 玩家只需懂 3 件事

| 玩家要记住的 | 数量 |
| --- | --- |
| 我这把兵器是什么元素 | 1 |
| 哪种痕和它同源 | 1 |
| 我想在地上留下什么（暗 / 亮 / 双光 / 湿 / 雾） | 5 选 1 |

> **160 种组合，认知成本是"3 件事"。** 这是所有"组合系统"能成立的门槛——**深度在组合里，认知在三条规则里。**

##### ⑦ 与既有规则的一致性

| 规则 | 是否冲突 |
| --- | --- |
| 3.12「融合与光尘双向率 100%」 | ✅ 更强了：痕现在同时改战斗判定与种植条件 |
| 3.13「光尘不改产出数量」 | ✅ 痕也不改产量（露痕给的是"多一颗露"，不是"产量 ×2"，且需手动采） |
| 3.20「不削弱专精」 | ✅ 痕对所有流派平等，纯农牧也能用"苔痕/暖痕"造地 |
| 3.7.9「零新键」 | ✅ 痕不占键，只在灯匠处配 |
| 3.3「10 配方」 | ⚠️ **定位变了**：从"手持道具"改为"兵器附痕"，名字与效果沿用 |

##### ⑧ 三条硬规则

1. **1 把兵器只挂 1 个痕**——2 个就变成 45 种组合，认知成本翻倍
2. **痕不改伤害数字**——只改判定与光场（否则会滑成"数值叠加型配方"，3.3 明令禁止）
3. **同源加成必须存在**——否则"元素"这一层就退化成纯配色

##### ⑨ 成本

| 项 | 数量 |
| --- | --- |
| 新绘制 | **0**（痕表现为"格子上的光场状态"，复用 3.7.11 的 8 种笔法与现有光域绘制） |
| 新音效 | **2 个**（配痕 / 痕碎） |
| 参数 | 10 痕 × 4 个数（范围/时长/耐久/同源倍率） |
| UI | 手账「引」页多一栏"痕" |

### 3.8 大世界### 3.8 大世界：L0 分区（推荐先做）

**不做无缝大世界**，做 4~6 个独立区域 + 一张世界图数据表。切区时保留状态，玩家体验上仍是"有地图、有远方"。

```json
{
  "zones": [
    {"id": "plum_garden", "rect": [0, 0, 960, 640], "neighbors": ["north_path"]},
    {"id": "long_night_edge",
     "rect": [1920, 0, 960, 640],
     "neighbors": ["plum_garden"],
     "battle": {"type": "night_watch", "waves": 1, "intensity": 2, "refresh": "per_night"},
     "exit_is_side_path": true}
  ]
```

每区一份 `data/world/<id>.json`：苗床、灯位、树位、NPC 锚点、出入口、`unlock` 条件。

**因为美术是程序绘制，切区是瞬时的**——玩家感觉不到加载。这是本项目的独特优势。

#### 五区五机制（v2 定稿）

每区尺寸统一 **960×640**（与现有地图同规格），因此 `forest_art.gd` 的绘制逻辑可整体复用，只需换配置参数。

| # | id | 名称 | 位置 | 独有机制 | 解锁条件 | 独有内容 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `plum_garden` | 月苔灯圃 | (0, 0) | 明暗共生 | 开局 | 已有：49 格苗床、3 盏灯、2 作物 |
| 2 | `moon_pond` | 月色水池 | (960, 0) | **倒影 = 第二光源** | `restored >= 1` | 作物「浮露苔」（需倒影光）；水面格不可站立 |
| 3 | `lantern_valley` | 灯路谷 | (0, -640) | **导光布线谜题** | `restored >= 2` | 导光苔枝 ×4、灯路节点灯 ×3 |
| 4 | `star_garden` | 星夜花园 | (960, -640) | **光色叠加** | `restored == 3` | 作物「星铃」（需暖杏 + 月青双光重叠）；蓝紫荧光 |
| 5 | `long_night_edge` | 长夜边界 | (1920, 0) | **守夜** | `restored == 3` **且亲自走到过一次** | 夜钟、雾蛾、光噬 |

##### 各区机制细节

**② 月色水池 `moon_pond`**

- 水面把苔灯的光反射成第二光源，**方向反转、强度 70%**。
- 水面格不可站立（`POND_RECT` 同类碰撞），所以"倒影光域"往往落在陆地上你走不到的位置 → 需要绕路或架桥。
- 独有作物「浮露苔」只能在倒影光里生长 → 这是**唯一必须靠物理布局而非开关灯**解决的种植条件。

**③ 灯路谷 `lantern_valley`**

- 4 根导光苔枝，要在地图上铺出从「源灯」到「3 个灯路节点」的连通路径。
- **v8 保底**：只需 2 根摆对即可连通（另 2 根是冗余物），且至少存在 3 条可行路线——**主线零谜题门**（3.18.6）。
- 连通判定用简单的四邻接图搜索，不引入寻路库。
- 完成一条灯路 → 解锁该方向的传送点（与 3.6 借光传送挂钩）。
- **这是把 v1 一直缺的"布线解谜"补上的地方**：现在游戏文案喊"重新连通林间灯路"（`garden_state.gd:170`），但代码里灯之间毫无关系。

**④ 星夜花园 `star_garden`**

- 「星铃」需要**暖杏光 + 月青光同时覆盖**该格（重叠带）才生长。
- 这直接复用 3.3 的「二向灯」和「灯光叠加」概念，不需要新系统。
- C 概念图的蓝紫、薄荷荧光、星形装饰全部用于此区，**不新增美术方向**（`README.md:54`）。

**⑤ 长夜边界 `long_night_edge`**

- 夜钟 + 2 种敌人（3.9）。
- `exit_is_side_path: true` —— **进出都不堵路**，绕开它就等于没打过（护栏 A）。
- 强度随「越靠近边界越浓的雾」递增，入口即可见（雾浓度 = 难度预告）。

##### 连接规则（防死路）

1. 每个区**至少与 2 个区相邻**（避免单点死路）。
2. `long_night_edge` 是唯一叶节点，但因为它 `exit_is_side_path: true`，不构成必经之路。
3. 所有区域**首次进入必须步行**（护栏 C）；之后才允许借光传送。

##### 入口坐标：实现时必须实测

现有地图的**南径 (420-600, 500-560) 实测 0 个可站立采样点**（树冠碰撞 101×119 吃掉下半圈），所以"南侧出口"不能照搬。建议实现时写一次性探测脚本：按 20px 网格扫描全图，剔除落在碰撞矩形外扩 10px 范围内的点，再按区域分组取中心点 —— 这就是本文档 1.2 节那张空位表的产生方式，可直接复用。

### 3.9 守夜（可选战斗）

#### 三层自愿闸门

| 层级 | 做法 | 解决什么 |
| --- | --- | --- |
| 元层 | 设置里「关闭夜钟」，连物件都不显示 | 完全不想打的人 |
| 游戏内 | 走到远处地点自己敲钟才触发，**无强制剧情** | 想打但今天不想打的人 |
| 局内 | 中途 Esc 直接走人，不结算不惩罚 | 打一半累了的人 |

#### 地点 + 夜钟（合并方案）

- **夜钟放在远处的战斗地点里**：走过去 → 看见钟 → 敲 = 开打；不敲 = 看一眼雾就走。
- **地点必须是岔路，不能在主路径上**（`exit_is_side_path: true`）。一旦"堵路"就变成强制战斗。
- **入口就能看到今夜强度**（雾的浓度 = 难度），走开零成本。
- **地点必须有节律刷新**（`refresh: per_night` / 每收 N 次 / 随灯路提升），否则就是"能走 5 秒的空按钮"。

#### 难度：进「条件」，不进「敌人数值」

| 难度来源 | 玩家应对 |
| --- | --- |
| 雾浓度 ↑ → 光域缩小 20% | 多插手提灯 |
| 潮汐 → 光域周期性抖动 | 掐时机开灯 |
| 湿气 → 某盏灯失灵 | 备灯 / 提前修 |
| 风向 → 雾蛾只从一侧来 | 提前布遮蔽物 |
| 长夜 → 时间压力 | 提高经营效率 |

**限制型难度不需要玩家手更快，只需要玩家想得更清楚。**

#### 守夜细节：预备帧 / 反馈 / 评级 / 敌人（v3 扩充）

##### 预备帧：可读性保障（v3 新增）

所有时间窗**必须有一个做在敌人身上的预备动作**。这是"不为难手残"的真正实现方式——不是把窗口放宽，而是**让难度可见**。

| 敌人 | 预备帧表现 | 时长 | 玩家在做什么 |
| --- | --- | --- | --- |
| 雾蛾 | 翅膀张开变亮 + 抬升 2px + 高频嗡鸣起音 | **0.45s** | 听到/看到就知道"下一秒要扑"，从容走进阴影 |
| 光噬 | 身体向内收缩 + 地面暗影先扩散 | **0.35s** | 暗影先到 = 提示"这里会变暗" |

**0.35~0.45s 预备 + 0.15s 判定窗口** → 玩家有 **3 倍于窗口的反应时间**去判断。所以"完美闪避"不是肌肉记忆，而是**观察力奖励**，正好是这个游戏的主题（看懂光照）。

反过来说，如果预备帧只有 0.1s，那就是欺负人——**能不能给手残玩家台阶，全看预备帧够不够长，而不是判定窗口够不够宽。**

#### 战斗反馈规格（v3 新增）

| 时刻 | 反馈组合 | 参数 |
| --- | --- | --- |
| 完美闪避 | **冻结帧 70ms** + 反相白闪 0.1s + 低频→高频扫频音 + 敌人光眩 | `hitstop 0.07` |
| 完美格挡 | 冻结帧 90ms + 圆环向外扩散 + 三音下行 + 反震光眩 2s | `hitstop 0.09` |
| 连锁（穿过敌人） | **冻结帧 120ms** + 全屏 0.15s 提亮 + 三音上行 | `hitstop 0.12` |
| 一夜 S 评级 | 三音上行 + 灯谱页盖章动画 | — |

**技术约束（重要，否则会毁掉像素画面）**：

- ❌ **不要用 `Engine.time_scale` 做慢动作**。它会同时拖慢 UI 和音频——`forest_audio.gd:15` 的 `VOICE_COUNT = 5` 音池不感知时间缩放，音效会变调；且在 640×360 像素画面上做时间缩放会产生亚像素抖动。
- ✅ **改用「冻结帧」**：手动暂停 combat 节点的 `process`。Godot 默认物理 60Hz → **1 帧 = 16.7ms**，所以 70ms ≈ 4 帧、120ms ≈ 7 帧，整数帧实现，像素不抖。

#### 评级：上限的展示位（社交货币）

| 评级 | 条件 |
| --- | --- |
| S | 零灯熄 + 完美闪避 ≥3 次 |
| A | 零灯熄，或完美闪避 ≥3 次 |
| B | 灯熄 ≤1 |
| C | 撑完这一夜 |

- **C 就是"打完了"**——手残玩家的目标；S 是高玩的炫耀面。
- 评级**不产出任何材料**（护栏 A），只进图鉴和手账。
- 存档进 `summary.night_grade`，属于 v2 已规划字段范围。

#### 共同规则（护栏 B 的实现方式）

- 敌人**不攻击玩家本体**（角色没有 HP），只攻击**灯**与**遮蔽物**。
- 所有损失作用于**镜像值**（敲钟时复制的 `charge` / `dew` 快照），天亮后丢弃并恢复。
- 因此"打输"永远不会让你变穷——这是护栏 B 的硬实现，不是设计口号。

##### 雾蛾 `moth`

| 项 | 规格 |
| --- | --- |
| 属性 | 被光吸引 |
| 行为 | 飞向最近的**点亮**苔灯，接触后扣除该灯 `charge`（−20% / 次） |
| 弱点 | 强光（`light_level > 0.8`）眩晕 1.5 秒 |
| 玩家反制 | ① 熄灯让它失去目标 ② 雾 / 深影囊改道 ③ 光引正面逼退 |
| 教学意义 | 教会玩家"灯既是资源，也是诱饵" |

##### 光噬 `devourer`

| 项 | 规格 |
| --- | --- |
| 属性 | 反向：追**暗处**移动 |
| 行为 | 沿最暗路径移动，吞掉路径上的深影囊 / 雾带 / 影烛（**破坏遮蔽物**） |
| 弱点 | 被光域覆盖时移速 −50% |
| 玩家反制 | ① 用光域围出走廊 ② 二向灯临时切换 ③ 露光致盲 |
| 教学意义 | 教会玩家"影不是无敌，是可以被吃掉的" |

##### 两种敌人的互补性（这才是设计价值）

- **雾蛾惩罚"全亮"，光噬惩罚"全暗"** → 任何单一策略都会被克制，玩家必须动态切换光照布局。
- 这正是把「明暗共生」这个核心从种植搬到战斗的落地方式。
- 两种敌人**都不堵路、不破坏经营状态**，玩家不打也完全没损失。

#### 经营即战力（夜间镜像）

| 经营成果 | 战斗里的身份 | 量纲 |
| --- | --- | --- |
| 已修复的灯 | 防线 / 容错次数 | 3 盏 = 3 次容错 |
| 露滴储量 | 弹药上限（镜像，**不真扣**） | 敲钟复制，天亮退还 |
| 光域半径 R=78 | 视野 / 有效射程 | 已有常量 |
| 遮蔽物 / 苗床布局 | 地形改造（改雾蛾路径） | 免费复用 |

**不做自适应缩放**（rubber-banding 会让努力失去意义）。

#### 数值参数

| 参数 | 值 |
| --- | --- |
| 单夜时长 | **45~60 秒**（≈2 个生长周期 18s / 24s） |
| 波次 | 一夜最多 1 波 |
| 首次失败率 | < 30%（熟练后 < 10%） |
| 重复练习 | 零成本，不消耗任何东西 |
| 操作 | 无连招、无闪避取消、无完美格挡 |

#### 好感度：只给情感，不给数值（v2 定稿）

| 好感等级 | 产出 |
| --- | --- |
| 0-1 | 基础对话 |
| 2 | 新对话分支 + 一段世界观碎片 |
| 3 | 外观解锁（苔林装 / 星夜装换装，`README.md:66-74` 已有概念图） |
| 4 | 猫玩具 / 家具布置变化（改变 NPC 所在区域的画面） |
| 5 | 图鉴条目 + 专属告别台词 |

**明确不给**（主人已定）：

- ❌ 不给任何数值加成（光照、产量、生长速度）
- ❌ 不给战力（不带诱饵灯、不带援护）
- ❌ 不给经营便利（不折扣、不代劳）
- ❌ 交易价格与好感无关

**为什么这样最安全**：好感一旦给数值，玩家就会把"和 NPC 聊天"变成任务清单——那是疲惫的来源之一。**只给情感的系统，才能被玩家按心情使用。**

好感获取方式（都不需要额外系统）：带 NPC 指定的东西、在他附近做对应的事（苔婆婆看她门前的苗床、钉铃看他修的灯）、摸猫。

#### 交易 ≠ 好感

注意区分两件事，否则容易写混：

| | 门灵 · 苔婆婆的订单板 | 好感度 |
| --- | --- | --- |
| 性质 | **资源交易**（露滴 / 灯孢 换遮蔽物、稀有种、换装券） | **情感进度** |
| 是否受好感影响 | 否 | — |
| 产出 | 可用道具 | 只有对话 / 外观 / 图鉴 |

**零美术成本**：NPC 就是 40 行 `draw_rect`，参考 `player.gd:36-86`。

**NPC 语音**：做一个 0.1 秒的 `blip`，所有 NPC 共用，逐字播放（`CUES:7` 加一行）。

### 3.12 跨系统联动矩阵（v5 新增）

> 回答「技能在战斗与种植之间到底怎么联动」。结论：**5 条通道，强度分三级，其中 3 处刻意断开。**

#### 3.12.1 五条通道

| # | 通道 | 方向 | 强度 | 机制 |
| --- | --- | --- | --- | --- |
| **① 共享接口** | 双向 | ★★★★★ | **光场 `light_level()` 是同一个数**：经营条件与战斗条件共用一套判定，改一个数两边同时变 |
| **② 镜像** | 经营 → 战斗 | ★★★★ | 敲钟复制经营状态：灯数 = 容错次数、露滴 = 弹药上限、R = 78 射程、遮蔽物 = 地形 |
| **③ 反向货币** | 战斗 → 经营 | ★★★★ | 夜露 → 修灯 / 夜灯；**夜苔 → 夜露** 形成闭环 |
| **④ 融合反哺** | 融合 → 经营 | ★★★ | 融合产物可种植：`shade_moss`（影苔）/ `warm_bell`（暖铃）需融合覆盖才能种 |
| **⑤ 光尘叠加** | 双向 | ★★★ | 光尘同时改战斗参数与种植条件，且**与融合可叠加**（3.13） |

**第 ① 条是根**：

```
经营：深影 < 0.15 才能种月苔
战斗：雾蛾只在亮处活动，阴影里失去目标
        ↑ 同一个 light_level()，同一个数
```

> **会种地的人自然会打仗，不是巧合，是因为两件事用同一个坐标系。**

#### 3.12.2 量化：谁在承担联动

| 层 | 双向 | 纯经营 | 纯战斗 | 双向率 |
| --- | --- | --- | --- | --- |
| **融合 10 配方** | **10** | 0 | 0 | **100%**（3.3 的硬规则强制） |
| 灯谱 12 节点 | 5 | 6 | 1 | **42%** |
| 光尘 4 种 | **4** | 0 | 0 | **100%**（3.13 的硬规则强制） |
| 作物 8 种 | 8（经资源间接） | 0 | 0 | 100%（间接） |

**关键结论：承担"玩法联动"的是融合与光尘（100%），灯谱只承担"操作流畅"（42%）。** 这个分工是对的——效率修饰类节点（省露/广收/速播）本来就不该有战斗语义。

#### 3.12.3 三个最完整的联动体

**① 深影囊 · 一物三用**
```
种月苔（经营）← 提供深影 ← 深影囊 → 遮蔽雾蛾 + 闪避点（战斗）
                                   ↖ 覆盖后可种「夜苔」→ 产夜露 → 买夜灯（反向闭环）
```

**② 雾 + 冲刺 · 跑过的地方变成田**
冲刺留雾带 → 雾里 `light_level ×0.5` → 你跑过的路线自己变成可种月苔的地 → 同时是战场遮蔽。叠加灯谱 `mist_trail`（雾带 2→3s）与 `mist_step`（穿雾不减速），同一行为在两种场景都被放大。

**③ 夜苔 ↔ 夜露 · 闭环**
```
纯守夜：打 → 夜露 → 修灯 / 夜灯
纯农牧：冬季种夜苔 → 夜露 → （一样能用）
```

#### 3.12.4 刻意断开的三处（设计而非疏漏）

| 断开点 | 内容 | 理由 |
| --- | --- | --- |
| **守夜评级** | S/A/B/C 只进手账，**不产任何材料** | 一旦给材料，手残玩家被迫打 S → 违反护栏 A |
| **NPC 好感** | 只给对话 / 外观 / 图鉴 | 给了数值，"聊天"变成任务清单 = 疲惫来源 |
| **借光传送** | **战斗中明确禁用** | 能传送 = 逃课 = 守夜节奏消失 |

> **通则：炫耀永远是炫耀，完成永远是叙事，战力永远是玩出来的。三者不能互相兑换。**

#### 3.12.5 三条联动补强（v6 定稿 · 已采纳）

##### 补强 ① 星铃「钉痕」——让作物第一次咬进战斗语义

| 项 | 规格 |
| --- | --- |
| 条件 | 守夜中，敌人走进**双光重叠带**（同时被暖杏光与月青光覆盖的格） |
| 效果 | 移速归零 **0.5 秒**，身上出现「钉痕」标记 |
| 连锁 | 钉痕可被**光引**击碎 → 击碎时向 ±1 格溅射伤害 |
| 边界 | 同一格每夜最多触发 **1 次**（防止无限钉） |
| 解锁前提 | 需先在星夜花园种出星铃（3.8 ④） |

**✔ 双向**：双光带在经营上是星铃的**生长条件**，在战场上是**陷阱**。会摆双光的人，自然有独门战斗技巧——不需要任何新系统。

##### 补强 ② 苔毯「留痕」——把弱功能换成信息功能

| 项 | 规格 |
| --- | --- |
| 效果 | 敌人走过苔毯 / 露苔毯会留下**足迹**（2 秒后消散） |
| 信息 | 足迹直接暴露它的意图（雾蛾追光、光噬追暗），玩家可预判下一步 |
| 附加 | 苔毯上的敌人**转向延迟 0.2 秒**（不是减速，是"判断慢") |

**✔ 理由**：只有 2 种敌人、且都不追玩家本体，所以"减速"和"潜行"意义有限。**这个游戏最缺的从来不是伤害，是"看清局面"。** 把弱功能换成信息功能，是本次补强里最有价值的一条。

##### 补强 ③ 点数余量：正式写进设计理由（不改动）

> **灯谱总数 11 点，全解锁需 8 点，纯守夜只需 5 点。**
> 所以任何专精玩家的"废点"最多 3 个，且**不影响任何目标**。灯谱**不需要**为专精玩家重新调整。
> 这叫**冗余预算**：给出去的总量略大于需求量，让"选错"永远有救。

### 3.13 光尘（Buff 系统 · v5 新增）

> 主人要的「一方面提升战斗效果，一方面作用到作物上」的 Buff。核心设计问题不是"做什么 Buff"，而是**它和融合怎么不打架**。

#### 3.13.1 分工：融合改「光」，光尘改「你」

| | 融合（3.3） | 光尘（本节） |
| --- | --- | --- |
| 作用对象 | **世界**：光场、遮蔽物、可种植区 | **角色**：移动、格挡窗口、交互范围 |
| 载体 | 手持道具（2 槽） | 服下 / 佩戴的粉末（1 格） |
| 时长 | 8~60 秒 | **一个白天，或一整夜** |
| 是否可叠 | 可同时带 2 个 | **同时只能 1 种** |

> 一句话：**融合改变战场，光尘改变你。** 两者不重叠，但可以叠加使用形成组合（见 3.13.4）。

#### 3.13.2 来源：灯火饱和时溢出的凝积物

**这是本节最关键的设计——不新增货币。**

> 灯亮着且 `charge` 满时，多余的光会缓慢凝成**灯芯屑**。灯芯屑 + 特定作物 = 光尘。

三个后果（全是好的）：

1. **零新货币**：灯芯屑就是灯火饱和的溢出，不占货币位。
2. **⭐ 和借光传送抢同一个资源**：传送消耗 `charge` → 灯火不满 → 灯芯屑停止积攒。**传送和 Buff 之间的取舍是白送的张力**，不用另做系统。
3. **"多修灯"有了第三条收益**：光域（经营）+ 传送点（交通）+ 灯芯屑（Buff）。

#### 3.13.3 四种光尘

| 光尘 | 原料 | 战斗效果（作用于你） | 种植效果（作用于你的操作） |
| --- | --- | --- | --- |
| **燃尘** | 灯芯屑 + 灯孢 | 格挡窗口 ×1.5、反震范围 +1 格 | 促长不耗露滴（3 次） |
| **润尘** | 灯芯屑 + 露滴 | 冲刺距离 +20%、雾带 +2 秒 | 收成 / 播种范围 +1 格 |
| **阴尘** | 灯芯屑 + 影苔 | 敌人索敌 −30%、完美闪避窗口 +50% | **深影加深一档**（浅影处也能种月苔） |
| **阳尘** | 灯芯屑 + 暖铃 | 射程 / 视野 +20%、光引 +1 格 | **暖光加深一档**（单灯即可补上星铃的一半条件） |

**三种光尘 = 三种玩家自我定位**：

- 燃尘 → 想打得更稳的人
- 润尘 → 想跑得更快的人
- 阴尘 / 阳尘 → 想改变光场结构的人（最贴近主题）

#### 3.13.4 光尘 × 融合的叠加（这才是"搭配"的第三层）

| 组合 | 结果 |
| --- | --- |
| 阴尘 + 深影囊 | 深影囊覆盖的格子变成**极深影** → 即使不在冬季也能种夜苔（但见下方硬规则） |
| 阳尘 + 光引 | 光引 3 格变 4 格，且亮度更高 → 一次性把一片苗床推到星铃条件 |
| 润尘 + 雾 | 冲刺更快 + 雾带更长 → "边跑边造田"的效率翻倍 |
| 燃尘 + 灯芯火 | 格挡窗口变宽，正好配合灯芯火的高风险高伤打法 |

#### 3.13.5 硬规则（防破坏经济与多样性）

1. **光尘只改速度 / 范围 / 条件，不改产出数量。** 产量永远由作物与季节决定。
2. **⭐ 稀有作物的季节限制不接受任何光尘减免。** 夜苔仍需"冬季 或 深影囊+阴尘"，回声铃仍需春/秋。否则光尘会变成经济的放大器。
3. **同时只有 1 种光尘生效**，切换会浪费当前剩余 —— 制造选择，避免加法爆炸。
4. **光尘不进灯谱**（和华丽层同理）：它是消耗品，不是进度条。
5. **战斗结束后光尘不退还**（守夜时服下的那一份就是那一夜的）。

#### 3.13.6 表现层

| 项 | 表现 |
| --- | --- |
| 服下 | 短促的"吸入"音效 + 角色身上浮起对应颜色的微粒（程序绘制，`draw_rect` 循环） |
| 生效中 | 手账「今日」页显示一个小标记 + 剩余时间 |
| 到期 | 一声很轻的"消散"音，微粒落下 |
| 提炼 | 灯匠处，把灯芯屑研磨成尘（研磨动画 = 2 秒的圆周运动） |

#### 3.13.7 战后余温：光尘的第二条获取途径（v10 新增）

> 主人提议：「战斗完给玩家一个种植 buff，补回双修玩家的亏损。」
> **方向对，但有一个陷阱必须绕开——绕开之后，这条机制的价值反而更高。**

#### 陷阱：不能是"额外加成"

如果做成"打完架 +20% 生长"，会立刻出两个问题：

| 问题 | 后果 |
| --- | --- |
| 纯农牧玩家没有这条路 | 他会觉得"我的效率天生比别人低" → 违反护栏 A 的**精神**（不卡进度，但制造了"次等人"感） |
| 变成"必须打架才高效" | 和 3.12.4「战力永远是玩出来的」直接冲突 |

#### ⭐ 正确解法：不是"多给一份"，而是"跳过攒料"

> **战后余温 = 一份你本来要自己攒的光尘，现在直接给你。**

对照一下：

| 玩家 | 拿到一份光尘的方式 | 代价 |
| --- | --- | --- |
| 纯农牧 | 灯亮着 → `charge` 满 → 灯芯屑自然凝积 → 灯匠处提炼 | **顺手攒**（约 2 分钟农活时间，无风险） |
| 双修 | **打完一夜，天亮时直接获得** | **60 秒战斗**（有失败风险、有操作压力） |
| 纯守夜 | 同上 | 同上（但他们本来就在打） |

**两条路的产出物完全相同、时间量级接近（120 秒 vs 60 秒）、风险不同。** 所以：

- 纯农牧**不会亏**——他只是多了一步"攒"
- 双修**补回来了**——省掉了攒的那一步
- **没有任何玩家获得"别人拿不到的东西"**

**这和 3.14.2「器具双途径」是同一个思想**：不是给更强的，是给"另一条路"。

#### 规格

| 项 | 规则 |
| --- | --- |
| 名称 | **战后余温** |
| 触发 | 守夜结束且**撑过**（灯熄了也算，中途逃走不算） |
| 产出 | **一份光尘**，直接进入 `dust.stock` |
| 类型 | 按当夜出现最多的敌人类别决定：雾蛾多 → **燃尘**；光噬多 → **阳尘**；两者相当 → **阴尘** |
| 生命 | 与普通光尘一致：**只作用一个白天**，到期消散 |
| 叠加 | **不叠加**：和自带光尘抢同一个槽（3.13.5 第 3 条），所以双修玩家打完不必再自己攒 |
| 上限 | **每季最多 8 份**（一天一份），**不可存储、不可跨日累积** |
| 评级影响 | **无**。S 和 C 拿到的完全一样（评级只负责好看，见 3.9） |

#### 三条护栏

1. **评级不影响数量**：否则手残玩家又被排除（护栏 A）
2. **不可囤**：防止"猛打三天囤一堆"变成刷子行为
3. **纯农牧等价路径必须一直存在**：灯芯屑自然凝积永远不能被关闭或涨价

#### 量化：它能补回多少

以纯农牧 = 100 单位时间为基线：

| 项 | 占比 |
| --- | --- |
| 种植照料 | ~55% |
| 守夜 | ~25% |
| 跑路 / 融合 / NPC | ~20% |

一份光尘的价值 ≈ 省下 **10~20% 的种植段操作时间**（少开关灯、少跑路），即约 **5.5~11 单位**。

```
双修原目标 1.15x (115)
  减去余温补偿       − 5.5 ~ 11
= 1.04x ~ 1.10x
```

> **结论：这条机制刚好把双修从 1.15x 压到 1.05~1.10x，落入合理区间，又不会让专精玩家觉得"我应该去打一架"。**
> 再猛就会伤专精——所以**上限就定在"一夜一份、只作用一个白天"**。

#### 与既有规则的冲突检查

| 规则 | 是否冲突 | 说明 |
| --- | --- | --- |
| 护栏 B「战斗零写入经营」 | ❌ 不冲突 | 余温在**天亮结算时授予**，不参与夜间逻辑、不改夜间数据 |
| 3.12.4「评级不产材料」 | ❌ 不冲突 | 余温是 **buff 不是材料**，且与种植自攒等价 |
| 3.13.5「光尘不改产出数量」 | ❌ 不冲突 | 余温就是光尘，继承全部硬规则 |
| 10.3「夜晚可以睡觉跳过」 | ⚠️ 需注意 | 睡觉拿不到余温——所以**必须**保留灯芯屑自攒（已列为护栏 3） |

### 3.14 器具封印（v5 新增）

> 主人提到"需要解开器具的封印"。这是**成长感的最佳载体**——因为它是**看得见的世界变化**，而不是数字 +1。

#### 3.14.1 只用一层，不要叠

**封印只在「器具」层，不在「技能」层。**

- 技能（灯谱 12 节点）= 点数 + 四途径解锁（3.5.1）
- 器具（6~8 件）= 封印 / 解封

两层用不同机制，**玩家不会同时面对两套"解锁条件"**。

#### 3.14.2 ⭐ 封印条件 = 「你已经做过这件事」

这是本项目的核心思想（环境许可替代能力许可，3.7.2）的延伸：

> **封印不是门槛，是"确认"。** 条件全部是玩家**顺手就能做到**的事，而且做到的那一刻，正好证明他理解了对应机制。

##### 双途径：每件器具都能「种出来」或「打出来」（v6 定稿）

主人要求解封既走种植方向也走战斗方向。落地方式：**每件器具两条解封途径，任一达成即解封，不叠加**。

| 器具 | 种植向解封 | 战斗向解封 | 解封后 | 教了什么 |
| --- | --- | --- | --- | --- |
| **灯谱**（手账页） | 修好第 1 盏灯 | —（基础必经） | 页签可见 | 修灯是主线 |
| **手提灯** | 第一次在深影里种活一株 | 守夜中靠阴影**脱战 3 次** | 可插地成临时光源 | **阴影既是生长条件，也是藏身处** |
| **融合器** | 第一次同时点亮 2 盏灯 | 用**光引逼退雾蛾 3 次** | 可做 2 属性融合 | **光可以叠加，也可以推** |
| **借光石** | 修好 2 盏灯 | **撑过 2 夜**（任何评级） | 借光传送可用 | 灯路需要两端 |
| **导光苔枝** | 完成一条灯路 | **零灯熄通过一夜** | 可铺满 4 根 | 灯路可以自己铺 |
| **光尘研磨** | 第一次攒满灯芯屑 | **完美闪避 5 次** | 可提炼光尘 | 灯火会溢出 / 时机可练 |
| **夜钟** | 三灯全亮 | —（守夜入口本身） | 可敲 | 战斗永远自愿 |
| **提灯远行** | 在灯路谷解完石匣 | **在雾里脱战 3 次** | 可携带一盏灯 | 灯可以移动 |

**共 8 件，上限 8 件。** 超过 8 件就会变成清单。

##### 双途径的三条规则

1. **种植向那条必须零操作技巧**：它是护栏 A 在封印层的落地——不会打的人照样能开满 8 件。
2. **战斗向那条必须是"技巧证明"而非"数量的 grind"**：脱战 3 次、零灯熄、完美闪避 5 次——都是**质量指标**，不是"打 100 只蛾子"。
3. **两条完成也不额外奖励**：解封是状态，不是成就分。

##### 为什么这个改法值得

| 玩家 | 他走的解封路线 |
| --- | --- |
| 纯农牧 | 8 件全走种植向 → 完整 |
| 纯守夜 | 除"灯谱/夜钟"两件必经外，其余全走战斗向 → 完整 |
| 双修 | 哪边顺手走哪边 → 最快的组合 |

> 这把"两条路都能走到底"（护栏 A）第一次覆盖到了**器具层**，而不只是经济层。


#### 3.14.3 解封的表现：让它有仪式感

| 层 | 表现 |
| --- | --- |
| 视觉 | 器具上的苔痕/封蜡**裂开褪去**（程序绘制：3 帧的矩形收缩）+ 器具轮廓从暗变亮 |
| 音效 | 一声"剥落"+ 一声上行的轻钟（`generate_audio.py` 新增 1 个 cue） |
| 文字 | 一句机制说明（不是"你获得了XX"，而是"原来阴影也能养东西"） |
| 手账 | 在「今日」页留一行小字，永久可查 |

> 解封文案的写法很重要：**要写成"我明白了一件事"，不是"我得到了一个东西"。**

#### 3.14.4 封印的边界

- ❌ 不做「封印需要材料」「封印需要等级」「封印需要好感度」——那都是门槛
- ❌ 不做「解封失败」——不存在失败
- ❌ 不做「封印会重新出现」——解封是永久的
- ✅ 封印状态进存档（`seals` 字段），跨周目/换档不丢
- ✅ 已解封的器具在画面上永久保持"无苔痕"状态

### 3.15 巡灯路线 · 离线生长 · 静观（v6 新增）

> 主人问的"自动寻路方便挂机"。我的判断是：**这个游戏该"自动"的不是走路，是时间。**

#### 3.15.1 先把「自动」拆成四件事，只有一个方向是对的

| 类型 | 内容 | 判断 |
| --- | --- | --- |
| AI 自动寻路 | 点地图一下，角色自己找路走过去 | ❌ **不做** |
| **巡灯路线** | 玩家先自己走一遍并录制，之后一键重走 | ✅ **做** |
| **离线生长** | 关游戏后，已种下的作物继续长 | ✅ **做** |
| 后台挂机产资源 | 关着游戏也产出露滴 / 灯孢 | ❌ **不做** |

**为什么 AI 寻路不行**：它直接杀掉本作唯一的核心度量——「位置 = 光照条件」。

```
玩家点一下地图 → 角色自己走过去
              → "我站在哪"不再重要
              → 光域规划 / 深影与暖光的取舍 / 借光传送，全部失效
```

**为什么离线生长可以**：它只推进**你已经决策过的东西**（种在哪、种什么），不替你做任何决定。

#### 3.15.2 巡灯路线

| 项 | 规则 |
| --- | --- |
| 录制 | 玩家自己走一遍（途中经过 ≥3 盏灯），自动记录为一条"巡灯路线" |
| 上限 | **3 条** |
| 重走 | 一键重走：角色沿路线移动，**遇敌 / 遇事件 / 遇可交互物自动停下** |
| 收益 | **零收益加成**。它只节省走路时间，不产出任何东西 |
| 边界 | 只能在**已走过**的区域使用（与借光传送同一条铁律） |
| 战斗 | **守夜中禁用**（与借光传送一致，见 3.12.4） |

> ⭐ **巡灯路线不产出资源，所以它不是"挂机脚本"，是"省时间"。** 玩家仍然必须亲自种、亲自收、亲自看光。

#### 3.15.3 离线生长（真正解决"累"的那一条）

| 项 | 规则 |
| --- | --- |
| 机制 | 存档写 `saved_at` 时间戳；读档时按经过时长推进**已种下**的作物 |
| 上限 | 最多推进 **1 个游戏日**（12 分钟）；超过就停在 1 日 |
| 推进什么 | 已种下作物的生长进度、季节与日数 |
| **不推进** | ❌ 不自动播种 ❌ 不自动收获 ❌ 不产夜间奖励 ❌ 不自动守夜 |
| 为什么上限 1 日 | 否则"离开一周回来收满仓"，所有人的节奏都会变成"关游戏等" |

**这一条才是"后台友好"的正确形态**：它让玩家**不必为了不浪费生长时间而挂着游戏**，但也不会替玩家把游戏玩完。

#### 3.15.4 自动化的三条红线

1. **不得替代决策**：选位置、选光照、选种什么，永远玩家做
2. **不得产出资源**：省时间可以，给资源不行
3. **守夜中一律禁用**：战斗必须是"人在场"的

#### 3.15.5 如果玩家真的想"什么都不干"

给一个诚实的答案：做**「静观」**，它是**「灯下」陪伴模式（3.17）的自动退化形态**。

站在原地不动超过 20 秒 → 进入静观模式：镜头轻微呼吸、萤火聚拢、时间照常流动、作物照常生长、**不弹任何 UI**。

静观中再站 60 秒 → 出现一行小字「按 `F` 坐下」→ 进入完整的**灯下模式**（有 BGM、有 6 种零后果交互、日历冻结）。

> 这不是挂机，是**允许玩家什么都不做**。
> comfort game 最该允许的事，恰恰是"待着"。

它的收益和站着完全一样（作物本来就在长），但它是**玩家的选择**，不是系统的代劳。

| | 静观（3.15.5） | 灯下（3.17） |
| --- | --- | --- |
| 触发 | 自动（20 秒不动） | 显式（按 `F`） |
| UI | 隐藏 | 隐藏 |
| BGM | 无 | **有（伴灯曲）** |
| 交互 | 无 | **6 种零后果交互** |
| 日历 | 照常推进 | **冻结** |

### 3.16 夹页与灯路图：替代任务日志（v6 新增）

> 主人问"NPC 的请求要不要进任务日志"。我的答案是：**要"不忘"，但不要"清单"。** 这两件事可以分开做。

#### 3.16.1 先区分三种东西

| 东西 | 例子 | 载体 | 会不会变成清单 |
| --- | --- | --- | --- |
| **一次性教学请求** | 灯匠："给我 3 个暖铃，我教你带走灯" | 不留痕迹，**说完就完** | 不会 |
| **持续性约定** | 苔婆婆："如果你有多的露滴，帮我留一些" | **夹页**（最多 3 张） | 不会（有上限） |
| **主线推进** | 五区灯路连通 | **灯路图**（世界地图） | 不会（是状态不是指令） |

#### 3.16.2 夹页：纸条，而不是清单

| 项 | 规则 |
| --- | --- |
| 形态 | 手账里**物理夹着的纸条**（最多 3 张叠在一起，有先后顺序） |
| 内容 | 一句话 + 一个需要的物件（**不写数量进度条**） |
| 优先级 | **没有**。按夹进来的顺序叠放 |
| 期限 | **软期限**：纸条边缘写"这个季节内"。过季**不失败**，只是纸条变旧发黄 |
| 完成 | **纸条自己消失**（不是打勾），夹页里留一行灰字 |
| 上限 | **3 张**。满了新纸条夹不进来 → 提示"手账先理一理" |

##### ⭐ 为什么"上限 3 张"是整套设计的关键

**有上限的约定才叫约定，无上限的叫待办列表。**

- 3 张：玩家记得住、做得完、不会焦虑
- 30 张：玩家会挑最划算的三个做，剩下 27 个变成心理债务 → 这就是"疲惫"的来源

#### 3.16.3 灯路图：主线的唯一可视化

| 显示 | 不显示 |
| --- | --- |
| 5 个区域节点 | 任务列表 |
| 灯路连线（连通则亮起） | 目标箭头 |
| 未连通方向的**雾中暗点**（看得见有东西，看不清是什么） | 距离 / 时间估计 |
| 玩家位置、已走过的区域 | 完成度百分比 |
| 熄灭的灯 | 「下一步去干嘛」 |

> **这张图回答"世界现在是什么样"，不回答"你该做什么"。**

#### 3.16.4 和「无人派任务」冲突吗？不冲突（v8 修订）

| 判据 | 说明 |
| --- | --- |
| 灯路图是**状态**，不是指令 | 没有"接受 / 放弃 / 追踪"按钮 |
| 夹页是**别人说的话**，不是系统派的活 | 它连"未完成"都不标注，只是变旧 |
| **唯一的判断标准** | **如果 UI 里出现"追踪任务"按钮，就是做错了** |

> ⚠️ **v8 重要修订**：这一节只否定「清单」，**不否定「方向」**。
> 光有地图和夹页，玩家仍会"不知道下一步该做什么"（主人已经指出这一点）。
> **方向感由 3.18 的三层引导模型负责**：L1 今日页三行目标 / L2 首次机制一句话 / L3 NPC 主动开口。
> 换句话说：**3.16 管"不制造债务"，3.18 管"永远知道下一步"。两者不是替代关系，是互补关系。**

#### 3.16.5 手账页签的最终形态（更新 10.8）

| 页 | 内容 | 解锁 |
| --- | --- | --- |
| 今日 | 季节/第几天、一句话目标、待办 | 开局 |
| **夹页** | 最多 3 张纸条 | 第一次收到 NPC 约定 |
| 灯谱 | 12 节点 + 剩余点数 | 修好第 1 盏灯 |
| 配方 | 10 个融合配方 | 第一次融合 |
| 图鉴 | 作物 / 敌人 / 地点碎片 | 进入第 2 区 |
| 人物 | 4 位 NPC 好感与故事 | 第一次和 NPC 说话 |
| **灯路图** | 5 区 + 灯路连通 + 雾中暗点 | 进入第 2 区 |
| **灯下轶事** | 3~5 个番外小谜题（不计入 100%，见 3.18.7） | 发现第一个轶事入口 |

### 3.17 「灯下」陪伴模式（v7 新增）

> 主人的原话：「有挂机功能，类似陪伴的效果，有 BGM，有交互动作，就像游戏背景一样，一直在黑夜中温和照耀的灯。」
>
> **这一句就是设计目标。** 本节只回答一件事：怎么做到"陪伴"，同时不破坏前面 16 节定的所有边界。

#### 3.17.1 定位：不是挂机，是"把游戏留成背景"

| | 普通挂机（手游语言） | **灯下（本作）** |
| --- | --- | --- |
| 目的 | 不在时也不亏 | **在不在，世界都一样** |
| 产出 | 结算弹窗、离线收益 | **零产出** |
| 心态 | 怕错过（FOMO） | **可以错过** |
| 时长统计 | 有 | **没有，永不统计** |
| 退出 | 领奖 | **直接走** |

> **灯下模式的身份是"壁炉"，不是"矿场"。**

它和 3.15.5 静观的关系：

```
站着不动 20 秒 → 静观（自动，无 UI）
静观中再站 60 秒 → 出现一行小字「按 F 坐下」
按 F → 灯下（显式模式，有 BGM 与交互）
```

**静观是灯下的自动退化形态**，灯下是静观的完整形态。玩家不需要知道这两个名字，他只会觉得"这个游戏可以就这么待着"。

#### 3.17.2 进入与退出

| 项 | 规则 |
| --- | --- |
| 进入 | 站在**任意一盏点亮**的苔灯 3 格内 → `F`；或暂停菜单里的「坐下」 |
| 退出 | **任意移动键 / `Esc` / 点击画面外** → 立刻回到游戏，**无确认框** |
| 强制退出 | 守夜开始、收到重大事件时自动退出（不会把你困住） |
| 记忆 | 记住上次坐下的位置，下次 `F` 直接回那里 |

**无确认框**是刻意的：陪伴模式必须"来得轻、走得也轻"。

#### 3.17.3 画面：一直在黑夜中温和照耀的灯

| 元素 | 表现 | 能否复用现有代码 |
| --- | --- | --- |
| **UI 全部隐藏** | 手账、提示、目标、种子卡一律不显示 | 现有 `hud.gd` 隐藏根节点即可 |
| **镜头缓漂** | 每 20~40 秒一次极缓的推近/平移，幅度 ≤8px，速度 ≤4px/s | 新增，`Camera2D` 位置插值 |
| **光域呼吸** | 视觉光域 78 → 80 → 78，周期 6 秒 | 新增（见下方技术提醒） |
| **萤火聚拢** | 萤火向灯附近漂移，数量不变 | 复用 `farm.gd:336-345` 的萤火绘制 |
| **雾在边缘流动** | 地图外围的雾缓慢平移 | 复用现有雾绘制 |
| **角色坐下** | 角色不再站立，改为坐姿（3 帧循环） | `player.gd` 的 `_draw` 加一个 sit 状态 |
| **偶发微事件** | 每 2~4 分钟一次：一片落叶飘过 / 一只萤火停在灯上 / 影猫走过来趴下 | 新增，低概率抽签 |

##### ⚠️ 一个必须提前避开的坑：光域呼吸不能影响判定

`is_lit()` 用的是 `const LIGHT_RADIUS := 78.0`（`garden_state.gd:18`），**如果让半径真的呼吸，光域边缘的作物会反复"暂停生长 / 恢复生长"**——玩家会看到作物进度条在抖，这是个很难受的 bug。

> **规则：光域呼吸只作用于画面，不作用于 `is_lit()`。**
> 视觉半径 ±2px，判定半径恒定 78px。

#### 3.17.4 BGM：伴灯曲

| 项 | 规格 |
| --- | --- |
| 形态 | **循环、无段落起伏、无鼓点**，3~5 个音，慢速 |
| 长度 | 60~90 秒循环 |
| 音量 | BGM **−14dB**；ambience 维持 −19dB；两者不抢 |
| 淡入 | 进入时**从静默渐入 8 秒**（不是"开始播放"） |
| 淡出 | 退出时 **3 秒淡出**，不切断 |
| 变体 | 四季各一个（同一段生成脚本换音阶/音色） |
| 生成 | 继续走 `tools/generate_audio.py`（Python 标准库合成） |

**和主游戏的隔离**：伴灯曲**不会带回主游戏**。它的功能是"陪伴"，拿去做背景音乐会让它失去特殊地位。

#### 3.17.5 时间：作物流动，日历冻结

这是本节最重要的规则，也是"陪伴"与"挂机"的分水岭。

| 东西 | 灯下期间 |
| --- | --- |
| 作物生长 | ✅ **照常流动**（这是既有规则，3.15.3） |
| 光照/光域 | ✅ 照常 |
| **日历（季节/第几天）** | ❌ **冻结** |
| 白天→黄昏→夜晚 | ❌ **不推进** |
| 守夜 | ❌ 不会自动开始 |
| 资源 | ❌ 不增不减（除了作物自己长熟） |

**为什么日历必须冻结**：

```
挂机 8 小时 → 若日历照常推进 → 回来发现"已经过了 8 天、过了两季"
            → 作物全熟成、季节跳了两个、错过了一堆东西
            → 玩家会觉得自己"被游戏玩过了"
```

> **规则：灯下模式让世界陪伴你，但不让世界跑在你自己前面。**

退出灯下时，日历从冻结点继续。

#### 3.17.6 六种交互动作（都零后果、可重复）

**判据**：任何交互都**不产出、不推进、不消耗**，只给"微反馈"。

| # | 动作 | 触发 | 反馈 | 有产出吗 |
| --- | --- | --- | --- | --- |
| 1 | **添灯芯** | 点灯 | 灯亮一度（+2px 视觉半径，2 秒回弹）+ 极轻的"呼"声 | ❌ 不增 `charge` |
| 2 | **摸影猫** | 点影猫 | 猫翻身、呼噜音、尾巴摆两下 | ❌ 好感日上限 +1（不累积成数值） |
| 3 | **摇灯铃** | 点成熟灯铃 | 清脆铃声，音高随机（Do~Sol 五声） | ❌ 不收获 |
| 4 | **拨萤火** | 点萤火 | 萤火四散，2 秒后聚回 | ❌ 无 |
| 5 | **看池水** | 点水面 | 涟漪 + 倒影晃动 3 秒 | ❌ 无 |
| 6 | **翻手账** | 点手账（隐藏中的） | 手账浮起一页，内容静止，再点收回 | ❌ 无 |

**为什么"添灯芯"不给 `charge`**：一旦给了，灯下模式就变成"刷灯火"的地方，借光传送的代价会被稀释。**视觉上像在添，数据上什么都没变**——这是本作一贯的做法（特效即信息，但不改数据）。

#### 3.17.7 回归反馈：它承认你离开过

这是"陪伴感"的核心表达。退出灯下时，按停留时长给一句话：

| 停留时长 | 一句话 |
| --- | --- |
| < 1 分钟 | （不说话） |
| 1~5 分钟 | 「你坐了一会儿。」 |
| 5~15 分钟 | 「雾散了又聚。灯还亮着。」 |
| 15~60 分钟 | 「夜色沉下去了。你回来得正好。」 |
| > 60 分钟 | 「你走了很久。灯一直亮着。」 |

**绝不说的话**：

- ❌ "离线奖励已领取"
- ❌ "你挂机了 45 分钟，获得 XXX"
- ❌ "今日在线时长：X 小时"

> 一句话的分寸感，比一整套挂机系统更能建立"陪伴"。**它记得你不在，但不责怪你不在。**

#### 3.17.8 健康与功耗（这个是白捡的）

| 项 | 做法 |
| --- | --- |
| **功耗** | 项目本来就是 **12fps 重绘**（`farm.gd:11` 的 `ANIMATION_STEP = 1.0/12.0`），灯下模式进一步降到 **8fps** → **挂机几乎不耗电、不烫机** |
| 眼睛提示 | 每 45 分钟一行小字：「让眼睛去看看真正的夜色吧」（可在设置关闭） |
| 光敏感 | 光域呼吸可关；伴灯曲可单独静音（与 `M` 键分离） |
| 声音睡眠 | 系统休眠后自动暂停 BGM，唤醒后 3 秒淡入 |

> **12fps 是这个项目最大的隐藏优势**：它天生就是"低功耗像素风"，不需要为挂机做任何额外优化。

#### 3.17.9 边界（必须写清的六条）

1. ❌ **不产任何资源**（灯芯屑也不给，见 3.17.6）
2. ❌ **不推进日历**（3.17.5）
3. ❌ **不自动种植 / 收获 / 守夜**
4. ❌ **不做离线收益结算弹窗**（这是手游语言，会立刻破坏基调）
5. ❌ **不做在线时长统计 / 排行榜 / 成就"坐满 10 小时"**
6. ❌ **伴灯曲不带回主游戏**

#### 3.17.10 技术接入点

| 需求 | 落点 |
| --- | --- |
| 隐藏 UI | `hud.gd` 根节点隐藏 |
| 镜头缓漂 | `player.tscn` 的 `Camera2D` 位置插值（注意它有 `position_smoothing_enabled = false`，需临时开启） |
| 光域呼吸 | `farm.gd` 的光域绘制里对半径乘 `1 + 0.025 * sin(t)`，**不动 `garden_state.LIGHT_RADIUS`** |
| 萤火 / 雾 | 复用 `farm.gd` 的动态层 |
| BGM | `forest_audio.gd` 新增第二个 `AudioStreamPlayer`（循环 + 淡入淡出），与现有 5 个音效 voice 分离 |
| 交互点击 | `farm.gd` 的 `_unhandled_input` 加灯下分支（点选世界物件） |
| 停留计时 | `main.gd` 记 `idle_started_at`，退出时算差 |

**注意**：`forest_audio.gd` 现有 `VOICE_COUNT = 5` 是音效池，BGM 不能复用（会被音效抢占）。必须独立播放器。

### 3.18 方向感 · 引导 · 谜题边界 · 番外（v8 新增）

> 主人的原话：「无论任务还是教程，都要有方向感。一味自由探索会像无头苍蝇。有目标后要能引导，而不是让玩家费劲查攻略。真要有解谜和探索，放到彩蛋、番外或单独活动更好，给玩家讨论与交流的空间。」
>
> **这一段话指出我之前一个判断失误，先认账。**

#### 3.18.1 认账：我把「方向感」和「任务清单」混为一谈了

我在 3.16 / 10.2 里写过「❌ 任务日志 / 任务追踪箭头 / 打勾列表」。**这个反的是"清单"，不是"方向"。**

| 概念 | 内容 | 结论 |
| --- | --- | --- |
| **方向感** | 我现在该干什么 / 往哪走 / 这一步怎么做 | ✅ **必须给足** |
| **任务清单** | 一串带勾选框、带优先级、带完成率的待办 | ❌ 仍然不做 |

> **新原则一句话：「只给下一步，不给全部。」**

方向感之所以和清单不同，是因为**它的信息量恰好是"一步"**：
- 清单告诉你 12 件事，你不知道先做哪件 → 焦虑
- 方向感告诉你 1 件事 → 安心

#### 3.18.2 三层引导模型（本节核心）

| 层 | 玩家的问题 | 载体 | **显示时机** |
| --- | --- | --- | --- |
| **L1 方向** | 该往哪走？ | 灯路图 + 远处灯光 + 今日页目标句 | **一直可见** |
| **L2 手段** | 这一步怎么做？ | 一句话「怎么按」 | **每个机制只在第一次** |
| **L3 兜底** | 我卡住了怎么办？ | NPC 主动开口 / 手账线索行 | **真的卡住时** |

**三层各有明确的显示时机，所以不会堆成一片提示。** 这是这套设计与"满屏任务指引"的根本区别。

#### 3.18.3 L1 方向：今日页升级为三行

现在的「今日」页只有一句话。升级为**三行**：

```
春 · 第 3 天
现在的目标：修好北边那盏灯
还需要：4 灯孢（灯铃在暖光里长）
```

| 行 | 回答的问题 |
| --- | --- |
| 第 1 行 | **我在什么阶段** |
| 第 2 行 | **现在做什么** |
| 第 3 行 | **还差什么、去哪拿** |

**不做**：进度条 / 百分比 / 任务编号 / 距离估算 / "剩余 3/5"。

**为什么三行就够**：玩家的注意力只有一格。**给一句"还差什么"，比给一串待办有用十倍。**

#### 3.18.4 L2 手段：首次机制引导（一句话）

规则：每个机制**第一次遇到时**给一句话，说完就走，**永不重复**。

| 机制 | 引导句（≤20 字，必须写"怎么按"） | 触发时机 |
| --- | --- | --- |
| 月苔 | 「阴影里才能种：站到光域外，按 `1` 再按 `E`」 | 第一次站在空苗床前 |
| 灯铃 | 「暖光里才长：走近苔灯按 `E` 点灯」 | 第一次在预热苗床前选灯铃 |
| 冲刺 | 「按 `Shift` 冲过去，能穿过矮栅栏」 | 第一次撞到矮栅栏 |
| 融合 | 「两个属性放一起：按 `3` 和 `4`，再按 `E`」 | 第一次拿到第二件属性物 |
| 借光 | 「已亮的灯之间能借光：按 `F`」 | 修好第 2 盏灯时 |
| 守夜 | 「想打就敲夜钟；不想打就回屋睡」 | 第一次黄昏 |

**三条硬规则**：

1. **只出现一次**，不重复、不弹出第二次
2. **必须写"怎么按"**，不能只写"是什么"（「阴影里能种月苔」是废话，「按 1 再按 E」才是引导）
3. **情境触发**：在玩家已经站在那个机制旁边时出现，不在开场灌输

> 判据：**如果一句话删掉后玩家会卡住 30 秒以上，它就该存在；否则删掉。**

> ⚠️ **v11 澄清**：「只说一次」指的是**不主动重复**，不是**查不到**。
> 忘了按键的玩家可以在手账「今日」页底部的**常驻速查行**里重看——**不主动弹 ≠ 查不到**（见 12.3 ⑥）。

#### 3.18.5 L3 兜底：不用查攻略的三个机制

| 机制 | 做法 |
| --- | --- |
| **NPC 主动开口** | 同一区域停留 > 3 分钟且无实质进展 → 最近的 NPC 说一句话（**状态驱动，读你的存档**，所以永远说的是你现在的问题） |
| **手账线索行** | 「今日」页底部一行浅色小字：「问问灯匠？」——**不是按钮**，是提示 |
| **"卡住"的定义** | 3 分钟内没有发生以下任一：收获 / 修灯 / 解锁 / 进入新区域 / 获得物件 |

**关键**：这三条都不叫"提示系统"，叫 **NPC 关心你**。

> 玩家永远不会点开一个「提示」按钮——但他会走过去跟灯匠说句话。**把帮助放进角色里，是这一节最重要的手法。**

#### 3.18.6 谜题边界：主线零谜题门

主人的判断是对的——解谜放主线会直接变成"查攻略"。

> **硬规则：主线路径上不允许任何"必须解开才能过"的谜题。**

三条保底手法：

| 手法 | 做法 | 例子 |
| --- | --- | --- |
| **冗余物** | 给的物件多于需要的 | 灯路谷 4 根导光苔枝，只需 2 根摆对即可连通 |
| **多解** | 至少 3 种解法 | 灯路可以用 3 条不同路线连通 |
| **可跳过** | 有绕路或替代手段 | 门锁着，但旁边有 1 格窄缝（冲刺进） |

**这和灯谱的「冗余预算」是同一个思想**：给多了，玩家就不会卡死。

#### 3.18.7 番外：「灯下轶事」（谜题该去的地方）

| 项 | 规则 |
| --- | --- |
| 名称 | **「灯下轶事」**，手账第 8 页 |
| 形态 | 收集式轶事页，3~5 个小谜题 / 小故事，每个 5~15 分钟 |
| 是否计入 100% | ❌ **不计入**（10.7 已定：只有 12 段故事 + 黎明） |
| 是否影响主线 | ❌ **完全独立**，随时可停、可跳过 |
| 如何触发 | 在世界里**发现入口**（不是被派） |
| 奖励 | 装饰（灯芯纹样、家具、称号），**无战力无材料** |

**三个例子**：

| 轶事 | 谜题类型 | 奖励 |
| --- | --- | --- |
| **石匣** | 要把光引到特定位置才开 | 一件旧工具（纯收藏） |
| **影猫的藏身处** | 跟着影猫走三次，它会带你去看它藏东西的角落 | 猫玩具 |
| **灯谱残页** | 4 张散落的残页，集齐可读上一任巡灯人的记录 | 一段叙事（不参与 100%） |

> **谜题放在这里，玩家就是"想解"；放在主线，玩家就是"必须解"。这两种心态差很远。**

#### 3.18.8 交流话题：让玩家有的聊，但不做排行榜

不做联网、不做排行，但可以**制造话题**：

| 机制 | 做法 | 产生什么话题 |
| --- | --- | --- |
| **光潮变异** | 每局季节相位 / 雾浓度随机 | 「我这边冬天特别长」 |
| **灯语分享码** | 把苗床布局编码成 8 位短码，可离线互相贴（不用服务器） | 「你的灯圃怎么摆的？」 |
| **轶事发现顺序** | 每个番外入口位置随机分配 | 「那个石匣你怎么开的？」 |
| **稀有作物** | 夜苔 / 回声铃的获取时机因季节而异 | 「你什么时候种出来的？」 |

> **话题来自"经历不同"，不来自"排名不同"。**
> 一有排行榜，话题立刻从交流变成攀比——那就不是"讨论心得"，是"内卷"。

#### 3.18.9 主动求助与阶梯提示（v9 新增）

> 主人补充：**「不是所有玩家都能沉下心不断尝试。」** 这句话是对的——3.18.5 只解决了"卡太久"的情况，没解决"我现在就想知道"。

##### 双通道，缺一不可

| 通道 | 触发 | 适合谁 |
| --- | --- | --- |
| **被动** | 3 分钟无进展，NPC 自己开口 | 玩家没意识到自己卡住了 |
| **主动** | **任何时候走到 NPC 面前按 `E`，选「我有点迷茫」** | 玩家已经知道需要帮忙，但不想等 |

**为什么主动通道仍然放在 NPC 的嘴里，而不是做成「提示按钮」**：

| 方案 | 玩家的心理 | 结论 |
| --- | --- | --- |
| 右上角「?」按钮 | "我用提示了，我菜" | ❌ |
| 找灯匠说句话 | "我问问灯匠" | ✅ |

> **同样一次求助，做成按钮就是"承认失败"，做成对话就是"找人聊天"。** 这个差别决定了玩家在真正需要时会用哪一种。

##### ⭐ 阶梯提示：问第 N 次，给第 N 级

同一个问题反复问，**每次往上加一级**，玩家可以随时停在合适的高度：

| 次数 | 层级 | 内容示例（"北边那盏灯修不了"） |
| --- | --- | --- |
| 第 1 次 | **方向** | 「北边还有盏灯。往那边的雾里走。」 |
| 第 2 次 | **具体** | 「那盏灯要 6 灯孢、4 露滴。灯孢从灯铃来。」 |
| 第 3 次 | **操作** | 「灯铃要暖光才长。挨着灯的苗床才亮。」 |
| 第 4 次 | **代做** | 「喏，我帮你把灯芯接上——下次你自己来。」（**直接完成这一步**） |

**为什么第 4 级必须是"代做"而不是"更详细的说明"**：

> 说明了三次还是不会的玩家，**再说明一次也不会**。这时候唯一有效的帮助是替他做，然后告诉他"下次你自己来"。
> **这不会伤害他的自尊，反而是在保护它。**

##### 求助的三条零成本原则

| 原则 | 说明 |
| --- | --- |
| **不扣任何东西** | 不扣露滴、不扣好感、不延长冷却 |
| **不留任何记录** | 不统计、不显示"你求助了 N 次"、不影响评级与 100% |
| **不设"不求助"成就** | 绝不做「全程不问人通关」这种成就——它会把求助变成羞耻 |

**判据**：**如果一个玩家用满 4 级提示之后仍然能获得完整的满足感，那这套设计才是对的。**

##### 谁来当"提示 NPC"

| NPC | 管什么提示 |
| --- | --- |
| 灯匠 · 钉铃 | 灯、融合、器具、灯路 |
| 门灵 · 苔婆婆 | 作物、季节、订单、NPC 故事 |
| 夜行旅人 | 主线方向、番外入口（**他只在三灯全亮时出现**，所以他的提示总是"关于远方"） |
| 影猫 · 咔嗒 | 彩蛋、隐藏位置（它不会说话，只会带路） |

> **四个 NPC 各管一类问题**——所以"找谁问"本身就是一个可学习的、有世界感的动作，而不是一次点击。

### 3.19 轻量外分享：灯语与留言（v9 新增 · 备选方案）

> 主人说：「讨论部分是外部的论坛 / wiki / 群聊，我不希望游戏本体太臃肿。但灯语、以及地图上显示玩家留言，可以作为备选方案，可以借鉴。」

#### 3.19.1 总原则：本体不承载社区，只做「能带出去的东西」

| | 放游戏里 | 放游戏外 |
| --- | --- | --- |
| 论坛 / wiki / 群聊 / 私信 | ❌ | ✅ |
| 好友列表 / 在线状态 | ❌ | ✅ |
| **灯语短码**（布局文字） | ✅ 生成与读取 | ✅ 贴在任何地方 |
| **留言灯**（一句话） | ✅ 生成与读取 | ✅ 贴在任何地方 |

> **判据一句话：游戏只负责「编码」和「解码」，不负责「托管」。**
> 一旦游戏要托管内容（服务器、账号、审核），它就会变臃肿——而且单机游戏没有理由付这个成本。

**这条原则同时保护了三件事**：项目的单机性质、玩家的隐私、以及开发成本。

#### 3.19.2 灯语短码（推荐先做，成本最低）

把苗床布局编码成一个短字符串，玩家贴到任何地方，别人粘贴进来就能看到你的灯圃。

| 项 | 规格 |
| --- | --- |
| 长度 | **9 位**（Base32：A-Z + 2-7，去掉易混字符 0/O/1/I）——**末位是校验位，不参与 payload**（v11 修正：8 位 = 40 bit 已被 payload 占满，没有校验空间，见 12.2 ③） |
| 编码内容 | 区域 id（1 位）+ 苗床覆盖（4 位）+ 灯具布局（3 位）+ **校验（1 位）** |
| 是否可逆 | **不可逆压缩**，只用于"呈现"，不能还原成你的存档 |
| 展示形式 | 只读的"访客视图"：能看到你的灯圃长什么样，不能改、不能拿材料 |
| 为什么不可逆 | 一旦可逆，就是存档交换，会有"抄作业"和"存档攻击"两种麻烦 |

**为什么这一条最值得先做**：

- 9 个字符，玩家**可以直接打在聊天框里**，不需要任何平台配合
- 它就等于一句"你的灯圃怎么摆的？" —— **话题天然产生，不需要做社区**
- 成本极低：一个编码函数 + 一个只读渲染

#### 3.19.3 留言灯（备选，需谨慎）

在地图上留下别人能看到的一句话，靠近时显示——借鉴《黑暗之魂》的留言与《死亡搁浅》的点赞，但**去掉点赞**。

##### 形态：用「短语拼装」而不是自由文本

| 方案 | 内容审核 | 表达力 | 结论 |
| --- | --- | --- | --- |
| 自由文本 | 需要审核（脏话/剧透/广告） | ★★★ | ❌ 单机项目不该背这个 |
| **三段式短语拼装** | **不需要审核** | ★★☆ | ✅ |

**三段式**（中文版）：

```
[这里] [有] [深影]
  ↑      ↑      ↑
位置词  动词  名词（各 12~20 个可选）
```

可选词表大概：位置词（这里/前面/高处/灯下/树后）、动词（有/藏着/通向/适合）、名词（深影/暖光/一盏灯/缝/猫/石匣/露滴）。

**组合数**：20 × 15 × 20 = **6000 种**，足够表达，且每一句都是安全的。

##### 三条必须的限制

| 限制 | 原因 |
| --- | --- |
| **必须绑定位置** | 只有靠近那盏"留言灯"才看得见，不能跨图喊话 |
| **有寿命**：7 个游戏日后变旧、14 日后消失 | 否则地图会被塞满，一年后到处是噪音 |
| **默认关闭**，首次进入问一次 | 不想看的人永远看不见，这是底线 |

##### 为什么去掉点赞

| 有点赞 | 没有点赞 |
| --- | --- |
| 玩家会为了点赞刷留言 | 留言只为"帮到人"而存在 |
| 出现"热门留言"排序 | 按距离显示，不排序 |
| 变成社交媒体 | 保持"路标"的性质 |

> **留言是路标，不是帖子。** 路标不会有人点赞，但每个走夜路的人都会看它一眼。

#### 3.19.4 备选方案的风险清单

| 风险 | 应对 |
| --- | --- |
| 留言剧透（"前面有石匣"） | 只允许短语拼装，且**番外内容不进词表** |
| 留言误导（故意写错的） | 玩家可以**只给自己看**、也可以单向关闭；且**留言永不阻挡路径**（它只是字，不是门） |
| 数据来源（没有服务器从哪来别人的留言） | **不自动获取**。只有玩家**主动粘贴**短码时才出现别人的灯/留言 → 零服务器 |
| 记录进存档导致体积膨胀 | 只存最近 20 条，且 `notes` 之外单独一个 `guest` 字段 |

#### 3.19.6 存档搬运：「收进箱子 / 取出箱子」（v12 定稿 · A2）

> 灯语只编码"布局"，**不是存档**。所以换电脑目前等于从零开始。

| 项 | 规格 |
| --- | --- |
| 入口 | 手账 →「箱子」页签（第 9 页，默认隐藏，首次打开时出现） |
| 收进箱子 | 导出一个 `mosslight-YYYYMMDD.moss` 文件到玩家选择的位置 |
| 取出箱子 | 选一个 `.moss` 文件导入，**先校验再覆盖**（校验失败一律不动原档） |
| 文件内容 | 完整存档 JSON + 4 字节魔数 + 8 字节校验 + 版本号 |
| 魔数与校验 | 魔数 `MOSS`（防止选错文件）；校验用 FNV-1a 32 位（防手改、防传输损坏） |
| 是否需要服务器 | **不需要**。玩家自己传（网盘 / U 盘 / 聊天软件） |
| 与灯语的分工 | 灯语 = **给别人看**（只读布局）；箱子 = **给自己搬**（完整存档） |

**为什么必须做**：这是"单机游戏"里玩家唯一能做的事——**他得能把自己的时间带走。**
而且它顺带解决了另一个问题：**玩家改档**。有正规的导出/导入，"改 JSON"就不再是唯一的搬运手段。

#### 3.19.5 优先级判断

| 方案 | 是否推荐 | 理由 |
| --- | --- | --- |
| **灯语短码** | ✅ **推荐做**（先做） | 成本最低、话题最强、完全离线 |
| **留言灯（短语拼装）** | ⚠️ **备选，后做** | 需要词表设计 + 开关 + 寿命，工作量是灯语的 3~4 倍 |
| 自由文本留言 | ❌ 不做 | 审核成本 + 攻击面 |
| 论坛 / wiki / 群聊 | ❌ **绝不做进本体** | 会让单机游戏臃肿，且需要长期运营 |

> **一句话结论：把社区留给社区，把"可以带出去的碎片"留给游戏。**

### 3.20 双修的角色定位：三层补偿（v10 新增）

> 上一轮我提了「轮作声明」（每季可声明本季专精，另一轨 −50%）。**主人否掉了，理由成立**：
> **轮作会让专精失去意义**——如果谁都能一季切换，"专精"就只是"连续四次选了同一个"，而不是一种身份。
>
> 所以改成：**不削弱专精，只补双修。** 三条补偿各管一件事。

#### 3.20.1 双修到底亏在哪（量化）

| 养成系统 | 纯农牧 | 纯守夜 | **双修** |
| --- | --- | --- | --- |
| 灯谱需点数 | 6 | 5 | **8**（余量只剩 3，其他两个是 5~6） |
| 累计加成 | 1.00x | 1.30x | **1.15x** |
| 遭遇的首次引导 | ~3 条 | ~3 条 | **6 条全遭遇** |
| 并行管理的链 | 1 条 | 1 条 | **3 条**（种植 + 融合 + 守夜） |
| 独占内容 | 0 | 0 | **0** |

三个亏损各需一个补偿，**不能用同一条机制糊过去**：

| 亏损 | 性质 | 补偿 |
| --- | --- | --- |
| **① 效率 / 时间** | 做两件事花更久 | **战后余温**（3.13.7） |
| **② 容错 / 点数** | 8 点需求 vs 11 点供给 | **第二轨点数折扣**（3.20.2） |
| **③ 认知 / 引导** | 六个机制一起压过来 | **引导按季节分期**（3.20.3） |

#### 3.20.2 第二轨点数折扣

> **解锁第二个轨道（战斗 ↔ 经营）的节点，成本 −1（最低 1 点）。**

| | 现在 | 改后 |
| --- | --- | --- |
| 双修需点数 | 8 | **6** |
| 双修余量 | 3 | **5** ← 与其他两人持平 |

主题上自洽：**光与影互相印证，学第二侧本来就该更快。**

**这条不伤专精**：专精玩家本来不需要第二轨的节点，折扣对他没有影响。

#### 3.20.3 引导按需投放（v12 修正：否决"按季节分期"）

> **原方案（已否决）**：春教种植、夏教融合、秋教传送、冬教守夜。
> **否决理由（主人指出）**：**季节性分期等于用日历替玩家决定兴趣。** 只玩守夜的玩家会在春天被迫学种田，只玩种田的玩家会在冬天被迫学战斗——这恰恰违反了「所有玩法都由玩家自主选择」。
>
> **换个角度看**：季节分期解决的是"双修玩家六个机制一起压来"，但病根不是**时间**，是**同时性**。

**新方案：引导挂在「玩家已经动手做的事」上，不挂在时间上。**

| 触发条件 | 教什么 | 玩家感受 |
| --- | --- | --- |
| 站在空苗床前 + 已选种子 | 月苔 / 灯铃的光照条件 | 我要种，所以教我种 |
| 第一次撞到矮栅栏 | 冲刺 | 我过不去，所以教我过 |
| 手里同时有两件属性物 | 融合 | 我拿到了，所以教我配 |
| 修好第 2 盏灯 | 借光传送 | 我有灯路了，所以教我传 |
| 第一次到黄昏且旁边有夜钟 | 守夜是可选的 | 天黑了，所以告诉我可以不打 |

**核心差异**：

```
季节分期 = 时间到了 → 你该学这个了     ❌ 系统安排
按需投放 = 你正在做 → 我教你怎么做     ✅ 玩家驱动
```

**这条同时解决了三件事**：双修不再被六个机制同时轰炸（因为只教他正在碰的）、专精玩家不会被迫接触另一轨、以及**任何兴趣组合都能得到恰好够用的引导**。

**为什么不需要担心"漏学"**：

- 3.18.5 的 **NPC 主动开口**覆盖"卡住"
- 3.18.9 的 **主动求助 + 4 级阶梯**覆盖"我想知道但没触发"
- 12.3 ⑥ 的 **常驻速查行**覆盖"我忘了"

> **三者相加，等于"永远学得到、但从不被灌输"。**

#### 3.20.4 双修真正的优势（写清楚，之前漏了）

2 槽搭配 25 组合 = 光类 5 × 苔类 5。**双修是唯一能随时吃满全部 25 组的人**：

| 玩家 | 跨轨搭配（如「夜灯 + 深影囊」） |
| --- | --- |
| 纯农牧 | 要拿"夜灯"（战斗侧器具）→ 得靠冬季夜苔换夜露 → **季节性可用** |
| 纯守夜 | 要拿"深影囊"（经营侧）→ 得等 charge 满攒灯芯屑 → **有条件可用** |
| **双修** | **随时可用** |

> 这是一个真实的"软独占"。**它的代价已经写进 1.15x 里了，不需要再补。** 但它必须在文档里写明——否则玩家自己发现不了，等于白做。

#### 3.20.5 三层补偿的总体效果

```
① 战后余温      → 1.15x 压到 ~1.05~1.10x（补效率）
② 点数折扣      → 容错从 3 点回到 5 点（补容错）
③ 引导分期      → 认知负荷从"同时六个"拆成"一季一个"（补认知）
```

> **三条都不削弱专精，只把双修从"两倍债务"变成"一年四熟"。**

### 3.21 交易与消耗：让溢出的东西有去处（v17 新增）

> 主人的两个动机：**① 消耗多余资源；② 填补"新章节之间的空窗期"。**
>
> 但这两件事都能把 comfort game 带歪——所以要先把红线钉死。

#### 3.21.1 四条红线（先钉这个）

| # | 红线 | 为什么 |
| --- | --- | --- |
| 1 | **不卖"更强的"** | 只卖看得见的：装饰 / 服装 / 外观 |
| 2 | **不做倒计时 / 每日刷新** | 那是 FOMO 引擎，会直接把"可以错过"改成"不能错过" |
| 3 | **不做限时折扣 / 节日限定** | 同上 |
| 4 | **买得到时间，买不到产量** | 种子 / 材料可以买，但**溢价极高**，只够应急，不比种划算 |

> **判据：如果商店里出现一个"买了会更有效率"的东西，就是设计错了。**

#### 3.21.2 四个摊位，复用现有四个 NPC（不新增角色）

| NPC | 摊位 | 卖什么 | 为什么是他 |
| --- | --- | --- | --- |
| **门灵 · 苔婆婆** | 种子铺 + 裁缝 | 应季种子、**季节外种子（×3 溢价）**、服装、影猫窝 | 她围裙口袋里总有种子，而且她会缝 |
| **灯匠 · 钉铃** | 材料铺 + 工坊 | 应急灯孢/露滴（**溢价 ×5**）、器具、**痕重配** | 他本来就管材料和修东西 |
| **夜行旅人** | **行商** | **装饰**、一次性道具 | **他背的那个布袋——终于有了解释：他是从南边带货回来的** |
| **影猫 · 咔嗒** | 不卖 | 只带你去它藏东西的地方 | 它不会做生意 |

> **旅人从"神秘角色"变成"行商"，但不影响他不说话、不点破身份**——他只是把东西放下，退后，等你挑。这反而让他更像一个"回来看看"的人。

#### 3.21.3 装饰体系（消耗主力，5 类）

| 类 | 例子 | 价格量级 | 换来的东西 |
| --- | --- | --- | --- |
| **灯具外观** | 石座纹样、灯罩形状、灯芯颜色 | 中 | 光域边缘的花纹变了 |
| **地面纹样** | 苔痕、碎石、落花、积水 | 低 | 脚下好看 |
| **围栏与门** | 木栏、石栏、藤门 | 低 | 边界好看 |
| **NPC 与环境** | 影猫窝、三只碗小屋的窗、旧木桥的栏 | 中 | **场景里多一样东西** |
| **服装** | 苔林装 / 星夜装（README 已有概念图） | 高 | 角色外形（3.4 已定：共用碰撞与动作） |

**原则**：装饰**不加任何数值**，只改画面。**一件装饰的价值 = 玩家愿意为它多看几眼。**

#### 3.21.4 消耗曲线：越后期越贵（这是消耗溢出的关键）

| 章节 | 新增装饰 | 单价 | 玩家此时的多余资源 |
| --- | --- | --- | --- |
| 第 1 区 | 6 件 | ×1 | 少量 |
| 第 2~3 区 | 8 件 | ×2 | 开始溢出 |
| 第 4~5 区 | 8 件 | ×3 | 明显溢出 |
| 黎明之后 | 每季 4 件 | ×4 | 大量溢出 |

> **装饰涨价不是通胀，是"给后期资源一个出口"。** 前期买不起，后期买得完——正好对上。

#### 3.21.5 一次性道具（旅人独有，5 种）

| 道具 | 效果 | 价格 | 会不会破坏游戏 |
| --- | --- | --- | --- |
| **一整夜的雾** | 一夜雾浓度 +2（守夜更容易） | 高 | 只影响一场，不影响成长 |
| **备好的灯芯** | 修灯时少 1/3 材料（一次性） | 高 | 只省一次 |
| **催熟粉** | 一格作物立刻成熟 | 中 | 不如自己种（3 格时间） |
| **干苔引** | 直接获得 1 灯芯屑 | 低 | 比自攒贵 |
| **南边的信** | 一段只说一次的话（纯叙事） | 中 | 零影响 |

#### 3.21.6 更新节奏：基线是装饰 + 轶事，机制与人物按准入条件加（v18 修正）

> ⚠️ **v17 曾写"不加系统"，v18 修正**：主人指出——**为了长期更新，机制与人物必须能加，不能定死。**
>
> 所以改成：**基线更新 = 装饰 + 轶事；机制与人物可以加，但必须过四道准入。**

| 更新类型 | 内容 | 频率 | 是否需要过准入 |
| --- | --- | --- | --- |
| **基线**（每次都有） | 装饰 6~8 件 + 轶事 1 个 | 每章 | ❌ 不需要 |
| **机制**（进阶） | 新光结构 / 新地形 / 新敌人行为 / 新痕 / 新兵器 | 至多每两章 1 个 | ✅ **必须** |
| **人物**（谨慎） | 新 NPC | 很少 | ✅ **必须 + 一条额外条件** |
| **数值** | 伤害 / 血量 / 等级 / 产量 | ❌ | **永不加**（见 3.23） |

##### 加机制的四条准入条件

| # | 条件 | 反例（不通过） |
| --- | --- | --- |
| 1 | **不引入新的数值轴** | "新兵器的伤害是 1.5 倍" ❌ |
| 2 | **只改判定或改空间，不改数字** | "敌人血量 +50%" ❌ |
| 3 | ⭐ **必须让至少一件旧内容变得更有用** | "新敌人和旧敌人一样追光"——旧内容没被激活 ❌ |
| 4 | **优先零新键表达** | "新增一个 F 键放技能" ❌（除非确实无法复用） |

> **第 3 条是这套设计的引擎**：一条新内容如果不让任何旧东西变有用，它就只是"更多的同样内容"，玩家不会觉得世界变厚了，只会觉得变长了。

##### 加人物的额外条件

| # | 条件 |
| --- | --- |
| 1 | 新 NPC **必须绑定一个机制或解释一件旧东西**（现有 4 人都是这样：苔婆婆=订单，钉铃=器具，旅人=装饰行商，影猫=带路） |
| 2 | **不许打乱"四人对应一个缺席者"的结构**（设定集 §2）——新人只能是"路过的人"，不能是"另一个知情者" |
| 3 | 新 NPC 的**好感产出只能是对话/外观/图鉴**（不破 3.10 的"只给情感"） |

#### 3.21.7 三条硬规则

1. **装饰永不进"完成度"**（100% 只有 12 段故事 + 黎明，10.7 已定）
2. **材料溢价 ≥ ×5，季节外种子 ≥ ×3**——低于这个数，玩家就会"用钱跳过种地"
3. **商店没有"新品"标记**——不上 FOMO 标签

### 3.22 长期留存：黎明之后（v17 新增 · D 项定案）

> 主人选了「有限收束」。落地方式是：**给一个明确的"讲完了"，然后留一扇门。**

| 阶段 | 内容 | 时长 |
| --- | --- | --- |
| 第 1 年（32 天） | 主线：五区灯路 + 12 段故事 + 黎明 | 约 8~12 小时 |
| **黎明之后 30 天** | 世界一天天变亮；第 30 天黄昏，四位 NPC 各留一句话（**最后一段剧情**） | 约 2~3 小时 |
| **「常夜之后」自由模式** | 季节循环、装饰收集、轶事回访、灯下陪伴 | **无限** |

**第 30 天的那四句话**（全篇最后一次说话）：

| 角色 | 台词 |
| --- | --- |
| 苔婆婆 | 「三盏都亮了。我不数了。」 |
| 钉铃 | 「工具留在这儿。谁来都能用。」 |
| 旅人 | （布袋留下了。袋子是满的。） |
| 影猫 | （跟着玩家走。这次它不回头了。） |

**之后做什么**：

- 季节继续循环，作物继续长
- 装饰收集（每季 4 件）
- 轶事可重复看
- **灯下陪伴模式永远可用**

> **不给"通关画面"，只给一次"大家都说完了话"的黄昏。**
> 之后世界还在，只是没有新的事了——**这正是 comfort game 该有的结尾。**

### 3.23 内容扩张：不加数值，怎么持续创新（v18 新增）

> 主人问：**如果不加数值，怎么不断创新战斗的可玩性和场景设计？**
>
> **答案一句话：数值恒定 → 玩家能力恒定 → 新内容必须是"新的问题"，不是"更大的问题"。**

#### 3.23.1 为什么"不加数值"不等于"没得创新"

| 扩张方式 | 靠什么制造新意 | 第 3 章加什么 | 玩家感受 |
| --- | --- | --- | --- |
| **数值式**（不做） | 更大的数字 | 敌人血量 +50%，你的刀 +50% | "我在原地，只是数字变大了" |
| **谜题式**（做） | 新的**规则/空间/组合** | 一种新地形 + 一种新光结构 | "我得换个打法" |

> **谜题式扩张的上限极高**：光结构 8 种 × 地形 8 种 × 敌人行为 6 种 = **384 种场景组合**，
> 而且一个伤害数字都不用加。

#### 3.23.2 四张「内容原子表」（新内容只能从这四张表里取）

| 5 | **遮挡光** | ✅ 雾/深影囊 | 主动制造黑暗 |

#### 3.23.3 场景设计模板（三步，不出新系统）

> **任何新场景 = 1 种光结构 + 1 种地形 + 1 种敌人行为。**

| 例 | 光结构 | 地形 | 敌人行为 | 得到的场景 |
| --- | --- | --- | --- | --- |
| **A** | 移动光（6） | 滑面（6） | 追光（1） | 光在滑面上一路滑走，雾蛾跟着光跑，你必须在它追上之前把灯挪到别处 |
| **B** | 镜面（5） | 高台（3） | 静止伏击（4） | 你的灯照在镜面上，反出一片假光域；真正的敌人蹲在光域外的死角 |
| **C** | 无光（8） | 藤蔓（7） | 追声（3） | 全黑，只能靠声音判断；藤蔓可以烧，但烧起来的声音会招它 |

> **三个例子里没有一个新数值。** 全部是"旧东西的新组合"。

#### 3.23.4 ⭐ 创新的真正引擎：让旧东西复活

> **一条新内容，必须让至少一件旧内容变得更值得用。**

| 新内容 | 让谁复活 | 怎么复活 |
| --- | --- | --- |
| 光噬（追暗） | **雾**（原本只是造田工具） | 变成战斗必需品 |
| 镜面地形 | **光引**（原本只是耕地工具） | 可以用来"伪造"一片假光域骗敌人 |
| 追声敌人 | **苔毯/留痕**（原本是弱功能） | 变成唯一能预判它的手段 |
| 无光场景 | **影猫**（原本只是彩蛋） | 全黑时它会带路 |
| 分裂敌人 | **网**（原本只是控制） | 变成"唯一能不打死它"的解法 |

> **这一条是判断新内容好坏的标准**：它如果只增加长度、不增加厚度，就是坏的。

#### 3.23.5 内容排期（未来 5 次更新，每次只取一个原子）

| 更新 | 新增 | 类型 | 让谁复活 |
| --- | --- | --- | --- |
| 第 1 次 | 镜像谷（镜面 + 高台 + 静止伏击） | 新区域 | 光引、杖 |
| 第 2 次 | 追声的「响苔」 | 新敌人 | 苔毯、留痕、冲刺克制 |
| 第 3 次 | 呼吸光（新光结构） | 新机制 | 借光传送（要算时机） |
| 第 4 次 | 会搬灯的「衔灯鸟」 | 新敌人 | 手提灯、背灯架 |
| 第 5 次 | 全黑洞窟（无光 + 藤蔓） | 新区域 | 影猫、火把、吹箭 |

> **五次更新，零个新数值。** 而且每一次都规定了"让谁复活"——**这就是可持续的扩张公式。**

#### 3.23.6 什么时候可以加数值（唯一的例外）

| 场景 | 允许吗 |
| --- | --- |
| 新章节的敌人"更强" | ❌ |
| **新的自限玩法**（如"孤灯模式"：一整夜只能用一盏灯） | ✅ 这是**加限制**，不是加数值 |
| **难度条件**（雾浓度/潮汐） | ✅ 同上 |
| **光尘/痕的时长与范围** | ✅ 它们本就是参数，不是战斗力 |

> **判据：让游戏变"更难"可以，让数字变"更大"不行。**

## 4. 存档 v2 规格（第 ① 步，不可调整顺序）

### 4.1 必须解决的四个问题

| 问题 | 现状 | v2 对策 |
| --- | --- | --- |
| 加字段即废档 | `garden_state.gd:238` 精确键集 + `:240` 版本硬等 | 校验改为「必需键存在 + 未知键忽略」，版本升为 2 并写迁移函数 |
| 加区域即废档 | `garden_state.gd:257` `plots.size() != 生成数` | 改为「子集校验」：每个 entry 必须落在合法苗床集合内，不再比总数 |
| 加灯即废档 | `garden_state.gd:281` `lanterns.size() != 灯位数` | 同上，按 id 匹配 |
| 大世界爆 1 MB | `garden_save.gd:19` + 全量存格 | **只存非空格**（当前 49 格中只有少数有作物） |

### 4.2 顶层 schema（v2）

```json
{
  "version": 2,
  "muted": false,
  "calendar": {"season": "spring", "day": 1, "play_seconds": 0, "dawn_reached": false},
  "player": {
    "pos": [488, 418],
    "zone": "plum_garden",
    "discovered_zones": ["plum_garden"],
    "visited_sites": ["plum_garden/far_lantern"]
  },
  "resources": {"dew": 2, "spores": 0, "nightdew": 0},
  "summary": {"total_harvests": 0, "nights_survived": 0},
  "crops": [{"x": 34, "y": 23, "crop": "moon_moss", "growth": 0.65}],
  "lanterns": [
    {"id": "plum_0", "restored": true, "lit": true, "charge": 1.0}
  ],
  "plots_by_zone": {"plum_garden": [[26, 18, 4, 4], [32, 21, 5, 4]]},
  "loadout": {"light": "lantern", "moss": null},
  "fusion": {"discovered": ["deep_shade"], "inventory": ["deep_shade"]},
  "dust": {"active": null, "expires": "day", "stock": {"embre": 2, "rime": 0, "shade": 1, "sun": 0}},
  "wick_dust": 4,
  "seals": {"codex": true, "hand_lantern": true, "fusion_table": false, "borrow_lamp": false},
  "routes": {"recorded": [], "active": null},
  "notes": [{"npc": "granny", "want": "dew", "since": "spring_3"}],
  "saved_at": 1793327602,
  "tree": {"nodes": ["grass_step", "borrow_light"], "points": 1},
  "npcs": {"granny": {"affinity": 3, "order": null}}
}
```

**要点**：
- `crops` **只存非空格**
- `calendar` 存季节与天数、**累计游玩秒数 `play_seconds`**（季节只认它推进，见 A3）、`dawn_reached` 是黎明纪元的标志（10.3、10.5）
- `plots_by_zone` 存苗床定义（分区后布局是数据，不再全部是 const）
- `lanterns` 用 **id** 而非索引，`charge` 是借光传送的灯火浓度
- `fusion` / `tree` / `npcs` 是**后加字段**，但因为校验改成宽松，v2 内继续加也不用再升版本
- **`dust` 存光尘**：`active` 当前生效的 1 种，`expires` 到期点（`day` / `night`），`stock` 各色存量（3.13）
- **`wick_dust` 存灯芯屑**（灯火饱和的溢出量，不是货币）（3.13.2）
- **`seals` 存 8 件器具的解封状态**（键为器具 id，值为 `bool`）（3.14）
- **`routes` 存巡灯路线**：`recorded` 为录制的路线数组（上限 3），`active` 为当前选中的路线（3.15.2）
- **`notes` 存夹页**：最多 3 条 NPC 约定，`since` 用于判断是否过季变旧（3.16.2）
- **`saved_at` 存时间戳**：离线生长按它推进已种下的作物，**上限 1 个游戏日**（3.15.3）
- 作物扩到 8 种（10.6）、货币扩到 3 种（露滴/灯孢/夜露）**都在本 schema 范围内**，不需要再升版本号

### 4.3 迁移规则

- 读到 `version == 1` → 补齐默认值（`nightdew: 0`、`charge: 1.0`、`tree.nodes: []`、区固定为 `plum_garden`）后按 v2 处理
- 读到 `version > 2` → 拒绝加载，提示"存档来自更新的版本"，**保留原文件不动**
- 现有 `.bak` 双档机制（`garden_save.gd:39-64`）保留

## 6. 实施顺序

> **顺序本身是设计的一部分。**

| # | 阶段 | 内容 | 成本 | 前置 |
| --- | --- | --- | --- | --- |
| ① | **存档 v2** | 宽松校验 + 只存非空格 + 分区 schema + charge/flags | M | 无（**必须最先**） |
| ② | 碰撞分层 + 动作状态机 | `_add_collision` 加 layer；`player.gd` 重构 **450 行** + 帧数据表 | M~L | ① |
| ③ | 冲刺 + 地形门控 | 0.06s 起手 / 0.9R 上限 / 输入缓冲 / 动量衔接 / 窄缝 | M | ② |
| ④ | 手提灯插地 | 最小动作收益：`lanterns` 加 temp 项 | S | ① |
| ⑤ | L0 分区 | `world.json` + 各区 json + 切区保留状态 | L | ① |
| ⑥ | 融合 3 配方 | 深影囊（经营向）/ 雾（造暗）/ 光引（跨轨） | M | ②、③ |
| ⑦ | 借光传送 | 灯火消耗 + `restored>=2` 门 | S~M | ⑤ |
| ⑧ | 守夜核心 | 地点 + 夜钟 + 雾浓度 + 2 敌人 + 预备帧 + 评级 | L | ⑤ |
| ⑨ | **战斗华丽层** | 完美闪避 / 完美格挡 / 3 招 × 2 段连招 / 情境派生 | L | ⑧ |
| ⑩ | 灯谱 12 节点 | 参数节点为主，灯匠处重置 | M | ⑥、⑦ |
| ⑪ | 双轨经济平衡 | 夜露、有损兑换、三档时长 | M | ⑧ |
| ⑫ | **灯下陪伴模式** | 无 UI + 镜头缓漂 + 光域呼吸 + 伴灯曲 + 6 交互 + 日历冻结 | M | ①、② |

> **⑫ 可以最先做**：它不依赖战斗、融合、分区，只要现有灯圃就能跑起来，而且**它是最能验证"这个游戏的气质对不对"的一块**——比任何玩法都便宜，也比任何玩法都更能让人记住。

**最小验证优先**：

- 阶段 ③（冲刺）：半天就能验证"位置是否变得重要"——只在现有地图加一道矮栅栏 + 一个窄缝
- 阶段 ④（手提灯插地）：一个下午验证"位置是否变成资源"
- 阶段 ⑥ 的「深影囊」：验证"融合能否扩展种植空间"
- 阶段 ⑧ 的「雾浓度系数」：验证"限制型难度是否真的不累人"
- **阶段 ⑨ 只用一件事验证**：玩家能不能闭眼听出"完美闪避"和"普通闪过"的区别

**为什么不按"先做战斗"排**：融合不需要战斗就能验证组合是否有趣；先有融合，战斗难度才能交给"条件"而不是敌人数值。反过来会让战斗先背负"没有成长"的压力。

**为什么华丽层（⑨）排在最后**：它需要状态机（②）、敌人（⑧）都就位才能测；而且它是唯一"砍掉也不影响通关"的模块，**风险最低，最适合被时间压力牺牲的那一块**。

**体量预警**：⑧ + ⑨ 合计约 **+820 行**（CombatDirector 200 / 雾蛾 120 / 光噬 140 / 格挡 80 / 连招 120 / 评级反馈 60 / 敌人绘制 100），项目会从 1676 行涨到约 **2500 行（+49%）**。这是本项目体量增幅最大的一块，需要主人确认是否接受。

## 7. 明确不做

- ❌ 完整动作战斗（挥剑 / 挥砍的肢体动作 / 命中判定盒）——**招式只能是位移 + 光效 + 音效的参数组合**（`player.gd` 无骨骼无贴图）
- ❌ 角色 HP / 攻击力 / 装备词条 / 技能 CD 条
- ❌ 深度技能树、天赋点、等级经验条（**12 节点是上限**）
- ❌ 连招规模超过 **3 招 × 2 段**（4 招 × 3 段 = 84 个分支，不可能做完）
- ❌ 靠**背输入表**的派生（派生必须靠"敌人状态"触发，见 3.7.8）
- ❌ 连招窗口窄于 **400ms**（400ms 是普通玩家反应区间；267ms 以下就是欺负人）
- ❌ **把连招 / 格挡 / 完美闪避放进灯谱**（会让手残玩家以为是必修）
- ❌ `Engine.time_scale` 做慢动作（会拖动 UI 与音频，像素画面亚像素抖动）——只用冻结帧
- ❌ 自适应难度（敌人跟随玩家变强）
- ❌ 战斗消耗真实经营资源（用镜像值）
- ❌ 战斗堵路 / 强制剧情战
- ❌ 敌人攻击玩家本体（角色无 HP；敌人只打灯与遮蔽物）
- ❌ 让玩家"被击中扣血"的惩罚性设计
- ❌ 免费无限传送、传送至未探索区域、付费加速灯芯
- ❌ 无损兑换（会让选择失去意义）
- ❌ 两套地图 / 两套进度
- ❌ 通用 N×N 道具融合矩阵（6 元素 = 21 个效果 ≈ 重写一遍游戏）
- ❌ 数值叠加型配方（+10% 光照这种）
- ❌ 序列帧 / 骨骼动画 / 贴图特效（一碰就要美术）

## 10. 叙事与结构（v4 新增）

> 本节回答的是「这个游戏到底在讲什么、玩家为什么往前走、走完是什么样」。前面 3~6 节全是"怎么玩"，本节是"为什么玩"。

### 10.1 世界观前提

**长夜是自然现象，不是灾难，没有反派。**

这个世界处在一个极长的冬夜纪。天不会完全黑——头顶始终有一层"月光似的微光"，但不足以让植物生长、不足以让人放心走远路。所以人发明了**苔灯**：把会发光的苔养在石座里，用灯芯点着，它就一直亮。

**苔灯的三层含义**（这是整个游戏的意义结构）：

| 层 | 含义 | 玩法对应 |
| --- | --- | --- |
| 第一层 · 照路 | 人能在夜里走路 | 光域 / `is_lit()` |
| 第二层 · 育物 | 月苔在阴影里长，灯铃在暖光里长 | 现有两种作物的对立 |
| 第三层 · 记忆 | 灯亮的地方，就是"有人在这里生活过" | 灯路 / 小镇 / NPC / 结局 |

**玩家是"巡灯人"——不是英雄，是接班的人。**

巡灯人的工作很朴素：每天巡一遍灯路，补灯芯，修坏掉的灯。游戏没有"你要拯救世界"，只有"上一任巡灯人不在了，这些灯总得有人管"。

> **这一句定调了全篇**：玩家不是在征服长夜，是在**替别人把灯继续亮下去**。所以"完整态"不叫通关，叫"接班完成"。

**为什么镇子空了**：长夜越来越长，灯一盏盏灭着没人修，人们陆续搬去了更亮的南方。剩下的灯还在原地亮着——只是光域缩成了一小圈一小圈，彼此不相连。

### 10.2 主线曲线：让世界自己带玩家走

**没有任务清单，没有 NPC 开口派活。** 主线是一条**物理的**线：灯路。

```
最南边的一盏母灯（永不熄灭，是起点也是兜底）
      ↓ 修好第 1 盏 → 光域扩大
      ↓ 光域照到的地方，露出第 2 盏灯的石座
      ↓ 修好第 2 盏 → 光域再扩大 → 远处雾里有微光
      ↓ ……
    五区灯路逐段连通
      ↓
长夜后的第一个黎明
```

**这个设计的核心价值**：主线提示不是 UI 箭头，是**画家里的光**。

- 每修好一盏灯，`LIGHT_RADIUS` 覆盖范围内会出现新的石座（`garden_state.gd:18` 的半径、`:15` 的灯位表天然支持）
- 玩家往哪走，不是因为有人说"去北边"，而是因为**北边有光，这边没光**
- 这是"无人派任务"唯一能成立的形式：**把任务写进地图，而不是写进对话框**

> ⚠️ **v8 补充（主人指出）**：光靠"远处的光"**不够**。它是**长程方向**，能告诉你"那边有事"，但告诉不了你"现在这一步该做什么"。
> 所以环境叙事必须配 **L1 今日页三行目标 + L2 首次机制一句话**（3.18.2）。
> **"把任务写进地图"是对的，但"只写进地图"就是错的。**

**环境叙事的四种载体**（都不用做任务系统）：

| 载体 | 用法 |
| --- | --- |
| 远处的微光 | 主线钩子。看不见光 = 那边没有人在 |
| 石座上的刻字 | 一句话碎片（"此处曾有三户人家"），靠近才显示 |
| 熄灭的灯旁的遗物 | 一个碗、一双鞋、一封信——不解释，只呈现 |
| NPC 的"路过" | 夜行旅人只在三灯全亮时出现，他不说话，只留东西 |

### 10.3 时间结构：日循环 + 四季

**一天**：白昼照料（可自由行动）→ 黄昏（**选择点**）→ 夜（守夜 或 睡觉）。

| 时段 | 时长 | 内容 |
| --- | --- | --- |
| 白昼 | 约 12 分钟实时 | 种植、收获、巡灯、NPC、探索 |
| 黄昏 | 约 30 秒 | **唯一的选择点**：去敲夜钟 / 回屋睡觉 |
| 夜 | 45~60 秒（守夜时）或 0（睡觉） | 守夜波次，或直接跳过 |

> **关键**：夜晚默认可以**睡觉跳过**。这就是"不打也能通关"在时间结构上的落地——不是"战斗可选"，是"夜晚可以不存在"。

**四季**：每季 **8 天**，一年 32 天。

> **季节怎么推进（v12 定稿 · A3）**：**只认游戏内游玩时长，不看系统时钟。**
> 白昼 12 分钟 = 一天；玩满 12 分钟才进下一天。这样：
> - 改系统时间**无法**刷季节（12.4 ⑦ 的漏洞关闭）
> - 存档只需记 `calendar.play_seconds`，与离线生长（3.15.3）解耦
> - 挂机在"灯下"模式里**日历冻结**（3.17.5），所以也不会白涨

| 季节 | 生长速度 | 深影占比 | 雾浓度 | 特征 | 最适合 |
| --- | --- | --- | --- | --- | --- |
| 春 · 萌苔 | **+20%** | 基线 | 稀 | 万物初醒 | 灯铃 |
| 夏 · 盛苔 | **+40%** | −10% | 重 | 湿气重（灯易失灵） | 灯铃 / 星铃 |
| 秋 · 收苔 | 基线 | **+25%** | 中 | 天光最短，露水丰 | **月苔** / 露滴 +1 |
| 冬 · 静苔 | **−50%** | **+40%** | 极浓 | 大部分作物休眠 | 夜苔（稀有） |

**四季只改"光照结构"，不改"光照时长"。** 这是本作季节系统与星露谷的根本差别——星露谷靠"作物生长天数"，本作靠**阴影与暖光的比例**。所以季节不是日历装饰，是**种植策略的轮换器**。

**冬季的特殊地位**：生长 −50% 看起来很惩罚，但它同时带来 **深影 +40%** 和 **夜苔成熟**。所以冬天不是"什么都干不了"，而是"该收月苔和夜苔了"。**每个季节都有它的作物。**

### 10.4 前 10 分钟

**不留任何"新手教程"界面**，全部用现有机制教学。

| 分钟 | 玩家在做什么 | 教了什么 | **L2 引导句（只说一次）** | 系统钩子 |
| --- | --- | --- | --- | --- |
| 0-1 | 在小屋门口醒来，手提灯是暗的；只有一盏灯亮着 | 移动、E 交互 | 「按 `WASD` 走，`E` 互动」 | `player.gd:72` 的手提灯 |
| 1-3 | 在阴影里种下月苔，18 秒后收获露滴 | **阴影 = 生长条件** | 「阴影里才能种：按 `1` 再按 `E`」 | `garden_state.gd:20`、`:90` |
| 3-5 | 想种灯铃，发现长不出来 → 去点灯 → 长出来了 | **光与影的对立** | 「暖光里才长：走近苔灯按 `E` 点灯」 | `is_lit():80` |
| 5-7 | 攒够材料修好第 2 盏灯 → **远处雾里浮出第 3 盏灯的光** | 主线第一次显形 | 「北边还有一盏灯」 | 10.2 |
| 7-9 | 冲刺穿过一道矮栅栏（唯一一处） | 冲刺 | 「按 `Shift` 冲过去，能穿矮栅栏」 | 3.7.7 |
| 9-10 | 第一次黄昏 → 提示"夜钟可以敲，也可以睡觉" | 守夜是可选的 | 「想打就敲夜钟；不想打就回屋睡」 | 10.3 |

**第 5-7 分钟是全局最重要的一分钟**：那是玩家第一次意识到"这个游戏有远方"。如果这一刻没做出来，后面所有大世界设计都不成立。

> 判断标准很硬：**玩家在 10 分钟内应该主动说一次"那边是不是还有灯？"**

### 10.5 结局：长夜后的第一个黎明

**触发条件**：五区灯路全部连通 + 三盏主灯修复。

**表现方式：不是 CG，是画面变化。** 项目的美术是程序绘制的，所以黎明可以真的"画"出来：

| 时刻 | 画面 | 声音 |
| --- | --- | --- |
| 第 0 秒 | 所有灯同时亮到最亮（`charge` 全满） | 全体灯的低频共鸣 |
| 第 2 秒 | **画面顶部出现一条极淡的暖色带**，缓慢下压 | ambience 里加入第一次出现的"鸟" |
| 第 5 秒 | 暖色带推到地平线，远处开始分辨得出山和树 | 长音渐强 |
| 第 10 秒 | 光域不再有边界——**整张地图全亮** | 音乐主段落第一次完整播放 |
| 第 15 秒 | 三位 NPC 各说一句话，影猫跳上屋顶 | 归为静默 |

**之后不停机**：

- 世界进入「黎明纪元」：天光变亮，深影变少（月苔变难种了——这是个温柔的代价，玩家能感受到时间流逝）
- 季节继续循环，NPC 故事可以继续看
- **没有"二周目"、没有"通关画面"**：黎明是个状态，不是结束

> 这一条是主人选的方向里最重要的一点：**comfort game 的终点不该是"结束"，而是"终于可以只在白天种地了"。**

### 10.6 作物谱系

现在 2 种，计划 3 种。**完整谱系应该是 4 层 8 种**，每层和一种系统挂钩：

| 层 | 作物 | 生长条件 | 收获 | 与谁挂钩 |
| --- | --- | --- | --- | --- |
| 基础 | 月苔 `moon_moss` | 深影 | 露滴 ×3 | 秋 |
| 基础 | 灯铃 `glow_bell` | 暖光 | 灯孢 ×3 | 春 |
| 交叉 | 浮露苔 `dew_moss` | **倒影光**（月色水池） | 露滴 ×2 + 灯孢 ×1 | 夏 |
| 交叉 | 星铃 `star_bell` | **暖杏 + 月青双光重叠** | 灯孢 ×4 | 四季 |
| 稀有 | **夜苔** `night_moss` | **极深影**（冬季或深影囊覆盖） | **夜露 ×3** | 冬 |
| 稀有 | 回声铃 `echo_bell` | **半光带**（光域边缘，0.4~0.6） | 通用兑换物 ×2 | 春/秋 |
| 融合产物 | 影苔 `shade_moss` | 深影囊覆盖后种植 | 融合用暗色材料 | 任意 |
| 融合产物 | 暖铃 `warm_bell` | 灯芯火覆盖后种植 | 融合用光色材料 | 任意 |

#### ⭐ 一个重要的补漏：夜苔给夜露

之前双轨经济有个悬空的问题：**纯农牧玩家怎么拿到夜露？** 如果只能从守夜掉落，那"两条路都能走到底"就有暗坑。

**解法：夜苔产夜露。** 于是：

| 玩家 | 拿到夜露的方式 |
| --- | --- |
| 纯守夜 | 打 |
| 纯农牧 | **冬季种夜苔**（极深影 + 冬季加成，正好把冬天变成"攒夜露的季节"） |
| 双修 | 两边都拿一点 |

这使"有损兑换（夜露 : 灯孢 = 2:1）"这条规则第一次站得住——**它不是从虚空里来的货币，是可种植的**。

#### 四层谱系的相互作用

- **基础层** = 教学（月苔/灯铃就是前 10 分钟教的两个）
- **交叉层** = 地点机制（倒影、双光）→ 让区域有不可替代性
- **稀有层** = 季节机制（夜苔/回声铃）→ 让四季有意义
- **融合层** = 融合机制（造出的东西能种东西）→ 让融合反哺经营

> 每一层都必须**不可被上一层替代**。如果夜苔能在春天种，冬天就没意义；如果星铃能靠开关灯凑出来，星夜花园就没意义。

### 10.7 收集与「完成」的定义

**主人的选择：叙事向。** 所以主线完成度靠故事，不靠清单。

| 类别 | 数量 | 是否计入 100% |
| --- | --- | --- |
| **NPC 故事** | 4 人 × 3 段 = **12 段** | ✅ **计入（这就是 100%）** |
| **黎明** | 1 次 | ✅ 计入 |
| 灯路连通 | 5 区 | ✅ 计入 |
| 作物图鉴 | 8 种 | ❌ 额外目标 |
| 配方图鉴 | 10 个 | ❌ 额外目标 |
| 敌人图鉴 | 2 种 | ❌ 额外目标 |
| 地点碎片 | 20 条刻字/遗物 | ❌ 额外目标 |
| 守夜评级 | S/A/B/C × 5 区 | ❌ **纯炫耀，不计入** |
| **灯下轶事（番外）** | 3~5 个 | ❌ **不计入**（想解就解，见 3.18.7） |

**100% = 「12 段故事全部看完 + 达成黎明」。**

理由：评级和收集是**高玩的自我挑战**，一旦计入完成度，手残玩家就被迫去打 S——那就直接违反护栏 A 和护栏 B 的精神。**让炫耀永远是炫耀，让完成永远是叙事。**

#### 12 段故事怎么解锁（对应好感 3/4/5）

| 好感 | 解锁 | 内容方向 |
| --- | --- | --- |
| 3 | 第一段 | 这个人是谁 / 从哪来 |
| 4 | 第二段 | 他和上一任巡灯人的关系 |
| 5 | 第三段 | 他为什么留下来 |

> **三段的递进逻辑是"身份 → 关系 → 选择"**。第三段（为什么留下来）是真正打动人的那一段，也是所有 NPC 共享的主题——**因为玩家的答案也是这个**。

### 10.8 手账本（信息架构）

**手账不是菜单，是道具**——它是巡灯人的工作本。

> **v6 更新**：页签由 6 个扩为 **8 个**（新增「夹页」，原「地图」定名「灯路图」，v8 增「灯下轶事」）。
> **以 3.16.5 的最终版为准**，本节保留 v4 的原始思路与设计要点。

| 页 | 内容 | 何时解锁 |
| --- | --- | --- |
| **今日** | 季节/第几天、当前目标一句话、待办 | 开局 |
| **夹页** | 最多 3 张 NPC 约定的纸条 | 第一次收到 NPC 约定 |
| **灯谱** | 12 节点树 + 剩余点数 | 修好第 1 盏灯 |
| **配方** | 10 个融合配方（已发现的显示，未发现的显示轮廓） | 第一次融合 |
| **图鉴** | 作物 / 敌人 / 地点碎片 | 进入第 2 区 |
| **人物** | 4 位 NPC 的好感与已解锁故事 | 第一次和 NPC 说话 |
| **灯路图** | 5 区 + 灯路连通状态 + 雾中暗点 + 玩家位置 | 进入第 2 区 |
| **灯下轶事** | 番外小谜题收集（不计入完成度） | 发现第一个轶事入口 |

**设计要点**：

- **「今日」页是最重要的一页**：玩家 80% 的时间只会看它。它只写三样东西：什么季节第几天、现在该干什么、还缺什么。
- **未发现的配方只显示轮廓**（3.7.8 的"环境许可"思路）——让玩家知道"还有东西没造出来"，但不知道是什么
- **不做"任务日志"**：没有任务系统，只有目标和图鉴

### 10.9 卡关兜底（无死亡的另一种保障）

无死亡不等于不会卡住。逐条封死：

| 可能卡住的地方 | 机制兜底 | 出处 |
| --- | --- | --- |
| 材料不够修灯 | 种子免费 + 作物永远可再生；母灯永不熄灭 | `garden_state.gd:161-171` |

### 10.10 音景结构

现有只有一段 14 秒的 `forest_ambience.wav`（`forest_audio.gd:6`）。完整音景应该分五层：

| 层 | 内容 | 现状 |
| --- | --- | --- |
| 底层 · 环境 | 林间环境循环 | ✅ 已有 |
| 季节层 | 四季各一段 ambience 变体（同一段生成脚本换参数） | 待做 |
| 时间层 | 昼 / 黄昏 / 深夜三段，交叉淡入 | 待做 |
| 事件层 | 修灯、黎明、完美闪避等 | 部分已有（`CUES:7`） |
| **音乐层** | **伴灯曲**（3.17.4）与**黎明曲**（10.5） | 待做 |

#### 音乐规则（v7 改写）

> **v6 及之前的规则是「黎明那一段是唯一允许音乐的时刻」。v7 加入陪伴模式后，这条规则必须改，否则会自相矛盾。**

**新规则：音乐在本作出现两次，性质完全不同。**

| | 黎明曲 | 伴灯曲 |
| --- | --- | --- |
| 场合 | 结局（一次性） | 灯下陪伴（可反复） |
| 形态 | **有段落、有起伏、有主旋律**，完整演奏一次 | **无段落、无鼓点**，3~5 个音循环 |
| 功能 | **"发生了一件事"** | **"什么都没发生"** |
| 长度 | 约 60 秒，不循环 | 60~90 秒，循环 |
| 音量 | −10dB（最强的一次） | −14dB（背景级） |
| 是否带回主游戏 | 是（它会成为之后的主旋律） | **否**（隔离，见 3.17.4） |

**为什么两者不互相贬值**：

```
黎明的音乐 = "你做成了一件事"     → 事件
灯下的音乐 = "你可以什么都不做"   → 环境
```

它们回答的是两个相反的问题，所以**不冲突，而是互补**。这也正好呼应 10.5 那句：comfort game 的终点不是结束，而是"终于可以只在白天种地了"——**灯下模式就是那个"之后"。**

#### 两条硬规则

1. **深夜 ambience 音量 −6dB**（在现有 `AMBIENCE_VOLUME_DB = -19` 基础上再降），让守夜的音效突出
2. **伴灯曲与音效池完全隔离**：`forest_audio.gd:16` 的 `VOICE_COUNT = 5` 是音效池，BGM 必须用独立播放器，否则会被修灯/收获音抢占

### 10.11 可访问性

光影是这个游戏的核心语言，所以**色盲 / 光敏感**的玩家在这里会遇到双重障碍。四条对策：

| 问题 | 对策 |
| --- | --- |
| **色盲读不出光域** | 光域不用色相区分，用**亮度 + 纹理**：深影=横纹、暖光=点阵、倒影=斜纹、双光=交叉。纹理由 `farm.gd` 的光域预览直接画 |
| **完全不想看颜色** | Tab 光域预览增加「数值模式」：每格直接显示光强 0~100% 数字 |
| **光敏感 / 闪光不适** | 闪光强度滑块 0~100%；冻结帧可整体关闭；光晕脉动可关 |
| **手部操作困难** | 所有动作可换键；格挡可改为长按；连招窗口可放宽到 500ms |
| **文字太小** | 手账字体 3 档 |

> **"数值模式"是性价比最高的一条**：它不需要任何新的美术，只是把 `light_level()` 的数字印在格子上，却让整个游戏第一次可以被"完全不看颜色"地玩。

### 12.2 P0 · 动手写代码前必须定的三件事

#### ① 进度曲线表（最要命的一条）

现在文档里所有数值都是"起调值"（±20%、−50%、8%/s…），但**没有任何一张表能验证它们彼此自洽**。

至少要定四个锚点：

| 锚点 | 玩家应该拥有 | 用来验证什么 |
| --- | --- | --- |
| **第 1 天末** | 1 盏灯、2 种作物、3~4 格苗床 | 前 10 分钟（10.4）是否够用 |
| **第 8 天末（第一季）** | 2 盏灯、融合器、第 2 区 | 春季节奏是否拖沓 |
| **第 16 天末（第二季）** | 3 盏灯、灯路 1 条、光尘 4 种齐 | 中期是否有断档 |
| **第 32 天末（一年）** | 五区连通或接近、12 段故事 ≥4 段 | 目标时长 1.00x 是否成立 |

> **缺这张表，前面 20 轮的数值全部无法验收。**

#### ② 文本量与字体预算

| 项 | 估算 |
| --- | --- |
| NPC 12 段故事 | 1 800 字 |
| 日常对话（4 人 × 20 句） | 1 600 字 |
| 引导句（30 条） | 600 字 |
| 刻字碎片（20 条） | 500 字 |
| 轶事（4 个） | 800 字 |
| 道具 / 配方描述（50 条） | 1 500 字 |
| UI 文案（约 100 条） | 1 000 字 |
| **合计** | **≈ 7 800 字** |

**字体约束（这个数字解释了 3.18.4 的"≤20 字"从哪来）**：

| 字号 | 全屏宽 640px | 手账面板半屏 320px |
| --- | --- | --- |
| 12px 中文 | 53 字/行 | **26 字/行** |
| 14px 中文 | 45 字/行 | 22 字/行 |
| 16px 中文 | 40 字/行 | **20 字/行** |

> **所以"引导句 ≤20 字"不是随便定的**：16px 中文在半屏面板里正好 20 字一行不折行。
> 若将来做本地化，7 800 字 × 目标语言 ≈ 一份完整翻译工作量——**这个成本要在写文案之前就知道**。

#### ③ 灯语短码位预算不足（这是已发现的一个真缺陷）

| 方案 | 位分配 | 校验位 | 后果 |
| --- | --- | --- | --- |
| 现文档 8 位（40 bit） | 区域 10 + 苗床 15 + 灯具 15 | **0 bit** | 打错一个字符 → **静默载入错误的灯圃** |
| **建议 9 位（45 bit）** | 区域 5 + 苗床 16 + 灯具 19 | **5 bit** | 可检出约 **96%** 的单字符错误 |

> 改法：`3.19.2` 的长度从 8 位改为 **9 位**，末位是校验位。**这条必须在实现前改，否则上线后改格式会让所有已分享的码失效。**
