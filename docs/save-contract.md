# 苔灯镇存档契约

> 状态：现行契约已在 `codex/slice-a-mvp` 接入。格式迁移、M1 布局补偿、文件选择与保护均有独立检查；`main` 仍保留 v1 基线。未来系统的非空结构尚未实现，本轮会拒绝不理解的非空状态以避免清空写回。
> [文档导航](README.md) · [建造计划](build-plan.md) · [决策记录](decision-register.md) · [冲突处理方案](issue-resolution.md)

## 1 范围与版本

本文件是存档字段、文件选择、校验和迁移的唯一主定义。中文显示名不入身份键；ID以建造计划为准。

- 文件容器沿用 `{"garden": {...}, "muted": false}`，`version`位于`garden`内。旧路线图把所有字段放顶层的样例已归档。
- `garden.version = 1`是当前样片；`2`是M0目标格式。
- v2可以添加有默认值的可选字段；字段含义改变、删字段或改变既有类型必须迁移，不能用“忽略未知键”替代版本管理。
- M0只改变存储契约，保留当前49格、18/24秒、收获3和修灯6+4的玩法。12格、90/120秒、收获1及递增成本属于M1内容调整。
- M0只为日历、离线和其他未来系统保存安全默认字段，不启用对应运行逻辑；本文件第6节是后续系统接入时的契约，不要求M0同时做出日历、灯下或离线生长。
- 不能保存/加载未经校验的整份字典直接覆盖运行状态；先构造临时状态，成功后一次替换。

## 3 字段校验与身份

容器必需`garden`字典；`muted`可缺省为`false`，存在时必须为布尔值。v2核心必需键为`version`、`selected_crop`、`resources`、`summary`、`crops`、`lanterns`、`plots_by_zone`，以及它们表中定义的核心子字段；缺失即拒绝加载。其余字段缺省时按第2节示例补安全默认值，存在时仍须严格校验，不能将类型错误当作缺省。

M0基线的`plum_0/plum_1/plum_2`三灯条目必需，`plum_0.restored`必须为`true`，保持v1约束。以后新增灯才可由内容迁移补默认状态，不能把原有灯丢失伪装成“新增字段兼容”。

| 字段 | 契约 |
| --- | --- |
| `selected_crop` | 保留当前种子选择；合法作物ID，不由兵器装备替代 |
| `content_revision` | M0为`legacy_49`，缺省亦为该值；M1迁移到`slice_a_12_v1`，只能按受支持迁移链改变；未知修订拒绝覆盖 |
| `crops` | 仅存非空格；唯一键为`(zone,x,y)`，不同区域允许同坐标；同一区重复坐标拒绝 |
| `growth` | 有限数，范围0～1；空格不序列化 |
| `plots_by_zone` | 布局必须匹配该内容版本允许的区域、矩形与基座规则；存档不能通过自造矩形扩地 |
| `lanterns` | 按稳定ID合并到内容定义；缺失新增灯用默认值；重复/未知ID拒绝；`lit`为真时必须已修复 |
| `charge` | 有限数0～1；M0迁移已亮灯为1、坏灯/熄灯为0；不凭此字段改变v1光照规则 |
| `player` | 区域存在、坐标有限且可站立；失效位置退回该区安全点，不放到墙里；M0仍沿用出生点进入 |
| `calendar` | 年≥1、日1～8、季节与阶段合法；时间为非负有限数；当日白昼计时0～720秒，边界与阶段必须一致 |
| `resources` | `dew/spores/nightdew`为0～999999整数；未知顶层扩展键可忽略，但已知字段不能容错成错误类型 |
| `summary` | 非负整数；`total_harvests`沿用当前上限999999999 |
| `loadout` | 无光尘时`element=null`，表现为素引灯杆；族内选型独立保存，器形必须属于对应元素 |
| `marks_by_weapon` | 激活附痕系统后，每个兵器ID最多一项`{mark,uses_left,offsource_phase}`；次数为0～8整数，0表示已失效；异源半次累积为0或1，不跨换痕继承；M0仅空字典 |
| `dust` | 使用`ember`而非旧样例拼错的`embre`；库存为非负整数；余温单独保存，不混入可囤积库存 |
| `routes` / `notes` | 各最多3条；M0空集合；启用系统时补齐非空条目schema与边界用例 |
| `story_seen` / `tutorial_seen` | 稳定事件ID的去重集合；事件表的`seen`映射为对应ID是否在集合内，不另存第二个布尔状态 |
| `story_variants` | `event_id→variant_id`映射；只保存首次完整播放采用的内容变体；无变体用`default`，必须属于该事件的合法版本 |
| `claimed_story_items` | 去重条目`{event_id,item_id}`；与故事完成、首次变体及库存变更一次提交；回看不再次赠送 |
| `seals` / `tree` | 解封和节点状态不能仅靠缺字段自动判定已完成；用明确默认值及合法ID集 |
| `muted` | 严格布尔值，仍在容器顶层 |

JSON读取后的数值应按字段归一化为整数或浮点数，然后比较语义。不能把`3`与`3.0`的序列化外观差异当作玩家数据损坏。

未来非空结构（NPC约定、巡灯路径、余温到期点、商店购买等）在所属里程碑补字段与测试；当前示例的空值只预留命名空间，不宣称完整游戏schema已经闭环。D02已采用临时田，不能把临时格写入永久`plots_by_zone`。不理解的非空玩法状态不能被旧程序当作默认空值写回；正式接入时按兼容能力提升`garden.version`并提供迁移，不能仅靠可选字段跨过旧程序的保护。

### 3.1 临时效果与结算的字段方案

下列字段为后续里程碑的落实方案，M0仅验证空默认值。提交点、到期保护与同源算法以[冲突处理方案](issue-resolution.md)第4～5节为行为依据，非空数据结构在接入时与版本一同启用。

| 字段 | 非空结构与约束 |
| --- | --- |
| `world_effects[]` | 每项有唯一`effect_id`、`source_kind`、来源动作、`zone`、格坐标和种类；长效种植许可还含`bed_kind=fixed/extra`、`state=active/retiring`、`expires_day_index`与资格；瞬时光效保存剩余有效秒数，不把两种寿命混为一个倒计时 |
| 临时许可与作物关联 | 作物仍以`(zone,x,y)`唯一保存；位置必须属于固定苗床或合法额外临时床，禁止孤立作物；`retiring`只保护该坐标当前这一株，禁止换种/续期；清空时同事务删除许可，额外临时床才删除，固定床恢复普通判定 |
| 临时床预算 | 额外床仅在登记候选格出现，每区`active+retiring≤4`为起调上限，不覆盖道路或碰撞区；固定床上的许可不占该额度，固定床永不删除 |
| `loose_dew[]` | `{drop_id,source_kind,source_action_id,zone,pos,claimed}`；动作ID持久化且在世界内唯一，战斗来源另有`battle_id`；一次露痕触发至多一条，`drop_id`唯一；`claimed=true`不再渲染或领取，领取记录与资源变化同事务保存 |
| `pending_battle` | `null`或含`battle_id`、进入绝对日序号、`phase=active/settling`、真实状态基线、镜像快照、已发生消耗/产出事件及结果的对象；最多一场；事件以动作/效果ID去重 |
| `last_settlement` | `null`或`{battle_id,day_index,result}`；用于拒绝已结算或更早日序号的重复结算。每个游戏日最多一场正式收入，训练不得写正式领取标记 |

绝对日序号从日历推导：`(year-1)×32 + season_index×8 + (day-1)`，春夏秋冬索引0～3。夜间临时田在次日日初提交时，以新日序号+1作为到期点。跨年、换季和离线都不能重置或延长该到期点；离线不跨日。退役床不自动成熟，季节资格仍照常检查。

同格现存的`active`或`retiring`许可不刷新到期日；重复施痕、事件重放和读档都不能续期。旧许可到期并清理后才可由新的合法动作建立下一份许可。

局内快照、已发生消耗和事件日志一起保存，不能只保存奖励候选而丢失耗材记录。结算将世界效果、夜露/余温、实际消耗、日界与`last_settlement`一次提交，再清除`pending_battle`；写入失败保持待结算。历史领取记录只可在来源事件已不可能重放后压缩，不能清了记录却仍允许同一动作再次投放。

剧情也采用同一原则：完整播放后再提交`story_seen`、首次变体和物件领取。旧档已有已看事件但缺变体时，按当前世界选合法回看稿并补记录；缺领取记录不能作为补发旧奖励的依据。灯下陪伴不提交剧情完成或物件，相关演出在普通剧情交互中进行。

## 4 文件发现与保护

| 用途 | 文件 |
| --- | --- |
| 当前主档 | `user://mosslight_garden.json` |
| 当前滚动备份 | `user://mosslight_garden.json.bak` |
| 写入临时文件 | `user://mosslight_garden.json.tmp` |
| v1迁移来源与独立保留档 | `user://mosslight_garden_v1.json`及其原`.bak`，迁移不覆盖 |

文件发现顺序：

1. 当前主档有效：使用它，不再读取旧名。
2. 当前主档缺失/损坏且当前备份有效：恢复当前备份。
3. 当前主档或备份存在，但二者均不可用：报告损坏并禁止自动保存；不静默回退到较老的v1进度。
4. 当前主档和备份都不存在时，才依次尝试v1主档与v1备份并迁移。
5. 任一优先候选识别为高于支持版本：提示来自更新版本、停止自动加载与写回；不得用旧版本覆盖它。

已有WIP采用“新主档→新备份→旧主档→旧备份”的候选顺序，优先方向正确；仍需补第3、5条停止条件。原文“先旧后新”已作废。

每次保存先完成临时文件的写入、flush及错误检查，再备份有效主档，最后替换正式文件。失败不修改当前内存状态，不用坏主档覆盖有效备份。滚动`.bak`只保留上一份有效当前档；旧v1文件承担长期迁移留档职责，两者不可混用。

## 5 v1到v2迁移

| v1位置 | v2位置/动作 |
| --- | --- |
| 容器`muted` | 原值保留；v1允许缺省，缺失时取`false` |
| `garden.version` | 1→2 |
| `selected_crop` | 原值保留 |
| `resources.dew/spores` | 原值保留；补`nightdew=0` |
| `total_harvests` | 搬到`summary.total_harvests` |
| `plots[]` | 非空项搬到`crops[]`，补`zone=plum_garden`，保留原坐标与进度 |
| `lanterns[0/1/2]` | 分别映射`plum_0/plum_1/plum_2`，保留修复/开关状态 |
| 其他 | 补本文件示例中的安全默认值；`saved_at=0`，不把升级耗时结算成离线生长 |

原v1必须先按v1规则完整校验；损坏的必需字段不能靠默认值伪装成合法迁移。迁移成功并写出有效v2后才进入正常保存流程；写回失败保留原档并明确报告，不能宣称迁移完成。

M0不缩小苗床，所以不折算作物。原WIP把存档迁移和12格调整放在同一步；其中“+2露滴、+1灯孢”是基于那次具体布局与样本的M1迁移预期，不是所有v1升级的固定奖励。

M1按建造计划第3.3节的D06坐标做内容迁移：原坐标在新布局合法则保留，否则月苔每株折1露滴、灯铃每株折1灯孢，不按成长进度倍增。折算、点亮真实母灯与`content_revision="slice_a_12_v1"`一次提交，分别提示实际补偿与母灯规则变化。不能把当前样本坐标硬编码成全体玩家的迁移规则，也不能重进反复补偿。M0对旧母灯开关的保留与M1的显式玩法调整分开验证。

## 6 时间与离线

- `calendar.play_seconds`只累计有效普通白昼时间，不归零；`day_elapsed_seconds`每天归零。
- 黄昏、守夜、暂停、灯下、离线不累计白昼时间；黄昏/守夜有各自的`phase_elapsed_seconds`。
- 暂停及灯下还必须冻结`phase_elapsed_seconds`；灯下仅在非守夜状态进入，不能借陪伴模式暂停或跳过战斗结算。
- 日历在睡觉或守夜胜/败/弃结算时增加一次；离线不跨日、不换季、不生成夜间奖励。
- 离线最多为既有作物推进720秒；仅在保存时有效的生长条件下推进，不播种、不收获。临时效果只能在其剩余有效时长内贡献生长，不能因读档无限延长。
- 系统时间倒退按0处理；超过上限截断。上限不是防改档或防调时钟的安全保证，文档不作此承诺。
- 多次读取同一个文件不能在内存中重复结算同一段离线时间；应用后更新基准并正常保存。未来版本/损坏档不进行离线结算。

## 7 必须验证的用例

| 用例 | 预期 |
| --- | --- |
| 合法v1完整文件 | 资源、种子、坐标、生长、修灯、静音全部保留；原v1文件字节不变 |
| v1缺必需字段/坏坐标/重复格 | 拒绝迁移，不改运行状态与原文件；合法缺省`muted`不属损坏 |
| v2保存再读回 | 已知字段语义相等；数值类型归一化；同区无重复格 |
| 两区域同坐标 | 作物分别保留，切区往返不覆盖 |
| 新旧档同时存在 | 使用有效新档；不重复迁移或发补偿 |
| 新主损坏/新备有效 | 恢复新备；不把坏主覆盖备份 |
| 新主新备损坏/旧档有效 | 报告损坏，禁止自动静默回档 |
| 高版本主档/旧版备份 | 拒绝加载，不用旧备覆盖高版本 |
| 写入/备份/替换失败 | 原有效档可读；错误明确，不能误报保存成功 |
| 离线/暂停/灯下（对应系统接入后） | 作物推进符合各状态规则，日历与资源不凭空增加；M0只验证字段默认值与往返 |
| M1布局变化 | 内容迁移仅一次；实际作物逐项处理，未损坏的存档可回退留档 |
| 临时田到期/换季/重进 | 空床清理、有株退役；不能重种/续期；原株手收后清理；季节不被豁免 |
| 结算中断/重复事件/领取重进 | 同一事务至多一次；资源、消耗和日历一起提交；写失败不进入下一夜 |
| 剧情中断/回看/旧事件缺版本 | 完整后首次交付一次；回看固定首次稿；兼容补版本不补奖励 |

所有文件测试使用临时路径，不读取或覆盖玩家真实存档。非空临时田、战斗和剧情用例在对应系统接入时验证，不要求M0同时实现完整游戏。

## 8 导入导出协议初案

本节是`.moss`完整存档箱子的格式主定义，尚未发布或实现。灯语9字符示意码是另一种受限格式，见冲突处理方案第8.1节，不能用于恢复完整存档。

| 偏移（字节） | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII魔数`MOSS` |
| 4 | 2 | 小端无符号容器版本，初版为1 |
| 6 | 4 | 小端无符号UTF-8 JSON载荷字节数N，`0<N≤1048576` |
| 10 | 32 | 实际载荷字节的SHA-256原始摘要，不是64字符十六进制文本 |
| 42 | N | 第2节形式的JSON容器；文件总长必须恰为`42+N` |

导入先检查魔数、长度和摘要，再检查支持的容器/garden版本与内容修订，最后调用同一存档校验器构造临时状态。全部通过后才备份当前有效档并原子替换；高版本、截断、追加垃圾、坏类型或写失败均保留原有效档。摘要仅用于发现损坏，不声称防篡改或身份认证。

实现前固定编码测试向量，验证往返、错误长度、非法UTF-8、校验损坏及失败不覆盖。旧“8字节校验/FNV32”格式作废；如果原型已有不同箱子文件，只能显式识别迁移，不能把旧文件误读为本协议。
