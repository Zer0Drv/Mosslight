## P0-① 垂直切片：先做这一个闭环

### 1.1 定稿：切片 A

| 项 | 内容 |
| --- | --- |
| 范围 | **月苔灯圃一区**（12 格 + 3 盏灯）+ 2 种作物 + 修灯 + 手账「今日」页 + **灯下模式** |
| **不包含** | 战斗 / 融合 / 痕 / 光尘 / 兵器 / 分区 / 守夜 / 传送 |
| 现有代码可复用 | **约 80%**（`garden_state` 的生长与光照、`farm` 的绘制与交互、`hud` 的框架、`save` 的写入） |
| 目标时长 | **20 分钟可玩闭环** |
| 验证什么 | ⭐ **A1 那套新数值对不对**（一天 35 个、修第 1 盏 1/3 天） |

### 1.2 为什么是 A，不是 B 或 C

| 方案 | 内容 | 判断 |
| --- | --- | --- |
| **A** | 灯圃 + 灯下 | ✅ **完全不碰战斗/融合/分区**；能把"经济手感"和"陪伴气质"两件事同时验掉 |
| B | A + 冲刺 + 1 兵器 + 1 痕 | 要动 `player.gd` 重构（450 行）和碰撞分层 → 前置太多 |
| C | B + 守夜 | 要动敌人 AI、评级、镜像 → 摊子太大，看不到结果 |

> **A 的最大价值：它是唯一一个"不用等任何其他系统"就能跑的东西。**

| # | 验收项 | 判定 |

## P0-④ 迁移的边界情况（用真实存档验证过）

### 4.1 实测：玩家现在有一份真实存档

```
%APPDATA%\Godot\app_userdata\苔灯镇 · Mosslight\
  mosslight_garden_v1.json      2 170 字节
  mosslight_garden_v1.json.bak  2 184 字节
```

内容实测：

| 项 | 值 |
| --- | --- |
| `version` | 1 |
| `resources` | `{"dew": 1, "spores": 0}` |
| `total_harvests` | 1 |
| `plots` | **49 条**（其中非空 **3 条**） |
| 非空作物 | `glow_bell (28,20) 1.0` / `moon_moss (24,27) 1.0` / `moon_moss (23,28) 1.0` |
| `lanterns` | 3 条：`[T/F, F/F, F/F]` |

### 4.2 ⚠️ 发现一个真问题：旧坐标在新布局里全部失效

v2 的灯圃改成 **12 格**（`balance-tables.md` 表 ③ 定稿），而旧存档的三个作物坐标是
`(28,20)` `(24,27)` `(23,28)` —— **它们在新布局里一格都不存在。**

而这三株都是 `growth: 1.0`（**成熟没收**），玩家实际会损失 3 次收获。

### 4.3 三条处理规则（定稿：方案 2）

| 方案 | 做法 | 判断 |
| --- | --- | --- |
| 1 · 直接丢弃 | 只保留落在新苗床里的作物 | ❌ 玩家丢 3 株成熟作物，会记得 |
| **2 · 折算补偿**（推荐） | 不在新布局里的作物按 `crop` 折成资源：月苔 → 1 露滴 / 个；灯铃 → 1 灯孢 / 个 | ✅ **简单、可解释、不丢价值** |
| 3 · 坐标映射 | 人工维护"旧格 → 新格"对照表 | ❌ 49×12 的映射表，且以后每次调布局都要重做 |

**折算规则**：

```
for plot in 旧 plots:
    if plot.crop == "" : 跳过
    if plot.cell 在新布局里 : 原样搬进 crops[]
    else : resources[露滴或灯孢] += 1     # 按 crop 折算
```

本次真实存档的结果：**+2 露滴、+1 灯孢**（两株月苔 + 一株灯铃），并在读档时给一句提示：

> 「旧苗床换成新的了。多的收成算在这儿。」

### 4.4 另外两条边界规则

| 情况 | 规则 |
| --- | --- |
| 旧档 `lanterns` 少于 3 条 | 按 id 补齐，缺的默认 `restored:false, lit:false, charge:1.0` |
| 旧档 `.bak` 也读不出来 | **两个都保留，不覆盖**，提示"这次先不保存"（沿用现有行为） |

## P1-④ 测试策略：三层

### 4.1 分层

| 层 | 测什么 | 怎么测 | 现有基础 |
| --- | --- | --- | --- |
| **L1 规则层**（纯函数） | `GardenState` 的所有判定 | 直接 `GardenState.new()`，不建节点 | ✅ `smoke_test.gd` 350 行 |
| **L2 存档层** | 写过、读回、迁移、损坏 | 临时文件路径，不碰真实存档 | ✅ `save_test.gd` 184 行 |
| **L3 集成层**（场景） | 输入 → 世界 → HUD | headless 起场景，模拟 `InputEvent` | ⚠️ 只有少量 |

### 4.2 新增系统怎么测（模板）

> **每个新系统必须写三类断言：边界 / 单向 / 不变量。**

| 系统 | 边界断言 | 单向断言 | 不变量断言 |
| --- | --- | --- | --- |
| **痕** | 8 次用完后变 `null` | 同源痕给完整效果，异源给减半 | **痕不改变任何资源数量** |
| **光尘** | 同时只有 1 种生效 | 换光尘会浪费剩余时间 | **光尘不改变产量** |
| **兵器** | 16 把秒伤落在 ±10% 区间 | 换元素 = 换整套兵器 | **兵器不改 `light_level()`** |
| **守夜** | 灯全熄 → 判败 | 败只影响余温 | **守夜结束后真实资源不变** |
| **时长** | 720s 进次日 | `play_seconds` 只增不减 | **灯下模式时 `play_seconds` 冻结** |
| **装饰** | 买过的不能重复买 | 装饰不进完成度 | **装饰不改任何数值** |
| **迁移** | v1 全量档能过 | 迁移后立即写回 v2 | **迁移失败不动原文件** |

### 4.3 三条测试纪律

1. **测试不许碰玩家真实存档**（沿用现有的临时路径做法）
2. **每条"硬规则"必须有一条测试守着**（护栏 A/B/C 各有对应断言）
3. **平衡数值不进测试**（数值会变，测试只验"关系"不验"数字"）

## 加机制的四条准入

1. 不引入新的数值轴
2. 只改判定或空间，不改数字
3. ⭐ **必须让至少一件旧内容变得更有用**
4. 优先零新键

## 加人物的三条条件

1. 必须绑定一个机制或解释一件旧东西
2. 不许打乱"四人对应一个缺席者"的结构——新人只能是"路过的人"
3. 好感产出只给对话/外观/图鉴
