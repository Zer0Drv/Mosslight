## 3. 切片 A

### 3.1 范围

月苔灯圃一区、12 格苗床、3 盏灯（开局 1 盏已修复）、月苔和灯铃、种植/收获/修灯、手账「今日」页，以及灯下陪伴模式。目标是形成约 20 分钟的可玩闭环，检验 A1 参数与陪伴体验。

战斗、融合、附痕、光尘、兵器、分区和传送不进入切片 A。手账先做今日页；夹页只保留数据接口，首次出现相关内容前不显示空页或灰色锁定页签。

修灯不自动移除或换种。新亮格若种着未熟月苔，暂停其生长并提示“这里变亮了，可换种灯铃”；玩家可免费移除重种，或关灯让它继续成熟。已成熟月苔照常可收。新档两株预种可分别放到 A 的 `(28,18)` 与 D 的 `(14,26)`，沿用样片生长进度；经济基线另用全株进度为 0 的明确模型，不混用预种提前量。

#### 几何核验记录

依据 `scripts/world/farm.gd`、`scripts/world/forest_art.gd`、`scenes/characters/player.tscn` 与 `scripts/characters/player.gd`：四边界、房屋、池塘、两段栅栏、树桩、24 个完整树冠及三灯碰撞，共 36 个矩形；角色脚底 8×6，中心相对角色为 `(0,-3)`，交互点向前 16px。

| 检查 | 结果 |
| --- | --- |
| 12 个 16×16 苗床格与全部静态碰撞矩形 | 无重叠 |
| 所有苗床中心距最近灯 | 最小 35.78px，大于 22px 基座排除半径，也大于 20px 灯交互优先半径 |
| A 六格到母灯距离 | 35.78–67.88px，全在 78px 内；不受另两灯覆盖 |
| 东灯格到母灯/东灯/西灯 | 113.14 / 45.25 / 237.86px |
| 西灯格到母灯/东灯/西灯 | 113.14 / 257.99 / 35.78px |
| D 四格到所有灯的最小距离 | 113.14px，大于 78px |
| 出生点 `(488,418)` 到交互站位 | 用真实脚底尺寸加 0.05px 余量、2px 四邻接搜索，12 格与三灯全部可达 |

可达站位示例：东灯格站 `(568,328)` 朝右，西灯格站 `(408,424)` 朝左；A 各格可在其南侧 16px 朝上；D 下排可从上排朝下操作。三灯分别可在 `(472,368)` 朝上、`(592,296)` 朝右、`(384,408)` 朝左交互。

这证明当前静态几何下有通路，不替代引擎内的移动、相机、遮挡与实际手感验证。实机复验时不得再把树冠只当树干。旧“8亮4暗且修两灯不改变任何苗床”的布局已被替代，仅保留在历史档中。

## 4. 存档与布局迁移

完整字段、默认值、文件封装和校验以 [存档契约](save-contract.md) 为唯一规范；本文件不维护第二份 JSON 样例。

### 4.1 M0 仅迁移格式

- 保留现有种子选择 `selected_crop`，不将其塞入没有种子字段的兵器 `loadout`。
- `plots` 转为仅存非空作物的 `crops`，每株明确 `zone` 与格坐标；灯按稳定 ID 保存。
- 新增字段只补默认值。M0 不借格式迁移改变生长时间、产量、成本或苗床布局。
- 全部迁移在临时结构中完成，类型/范围/引用校验通过才替换活动状态。
- 新主档优先于新备份。仅在两个新版文件均不存在时，尝试旧主档和旧备份的首次迁移；新档损坏不能静默回到旧进度。
- 未知高版本应停止加载并保留文件，不得回退旧档后覆盖。
- 首次迁移单独保留 v1 原档归档。滚动 `.bak` 只负责近期恢复，不承担永久回滚副本。

### 4.2 M1 布局变更补偿

之前已采纳的规则是：空格忽略；仍在新布局内的作物保留；落在新布局外的非空作物按新产量折算，月苔每株 1 露滴、灯铃每株 1 灯孢。该补偿属于布局更新，不能与 M0 格式迁移混为一件事。

历史样本有成熟灯铃 `(28,20)`、月苔 `(24,27)`、月苔 `(23,28)`，资源为 1 露滴、0 灯孢。按第 3.3 节的新布局，三株均落在范围外，结果为 3 露滴、1 灯孢。这是该样本的复算结果，不是所有玩家的固定奖励；后续改坐标需按合法格集合重新计算。

补偿需记录布局修订状态并保持幂等，避免重复读档再次补偿。提示根据实际折算数生成。旧记录对母灯是亮是灭存在差异，迁移 fixture 必须分别覆盖：M0保留原状态；M1内容升级明确点亮母灯并提示，不凭文档样本猜测原灯状态。

### 4.3 必须覆盖的存档情形

| 情形 | 预期 |
| --- | --- |
| 合法 v1 全量档 | 有效作物、资源、灯状态和种子选择保留；补齐新字段 |
| v1 部分损坏 | 失败不修改正在游玩的状态，不覆盖原文件 |
| v2 往返 | 所有已支持字段语义相同；整数类型正规化 |
| 新旧档同时存在 | 优先使用新版；不重复迁移或补偿 |
| 新主档坏、新备份好 | 恢复新备份；不让坏主档覆盖好备份 |
| 新主/备均坏但旧档存在 | 保留文件并提示恢复选择，不静默回退后自动保存 |
| 未来版本 | 明确拒绝，保留文件，禁用自动覆盖 |
| 同坐标不同区域 | 作物和灯状态互不串区 |
| M1 布局升级重复读入 | 补偿只发生一次 |

JSON 解析后的数值先验合法性，再将声明为整数的字段正规化为 `int`；不要依靠原始 Variant 类型一致来判断存档正确。测试字段和样本以契约为准。

不责备玩家，不用感叹号，尽量给出下一步。长度由实际组件宽度和字体测量决定，不能统一承诺“16px、20 字一行”；可换行，重要条件和资源数量不得截断。

### 8.1 首日基础守夜与兑换入口

M5 在母灯附近的非主路径侧边提供基础夜钟，第一天黄昏即可敲钟；不要求提前种植、三灯修好、NPC 好感或付费道具。基础场景至少提供一盏点亮的镜像灯与可用素引，能以空资源进入；真实资源/灯状态不能使起始局面立即无条件判败。

夜钟的材料兑换与入口同时开放，不依赖后期才出现的旅人或工坊；两夜之间仍可兑换。按数值表提供 `2 夜露→1 灯孢`、`2 夜露→1 露滴` 的单向起调规则。胜/败完整结束都发基础夜露，主动退出不发；每个游戏日只结算一场正式收入，训练不另发奖。

必跑用例：新档零播种→第一天黄昏入场→胜与败分别各走一遍→兑换 12 灯孢和 6 露滴→加开局 2 露滴完成首修；随后把真实露滴降到 0，再验证仍可进入基础守夜取得下一笔收入。镜像损失、退出、重复加载和多个入口均不能重复发同一天的收入。

### 8.2 临时田的到期处理

D02 已采纳临时方案：仅作用于已有苗床或预先标定的临时田候选格，结算后保留一个完整白昼。46 格永久苗床预算不变；每区最多同时占用 4 个额外临时格为后续起调方案，不进入切片 A。

到期时空的额外临时格清理；有作物的长效种植许可转为 `retiring`，只保留该株所需的土壤与光照资格，取消 +20% 增速，季节资格照常检查，禁止换种/续期。该株手收或移除后退出临时状态；额外临时格删除，固定床恢复普通判定。固定床同样保护现株但永不删除、不占额外额度；额外临时格在`retiring`期间仍占4格预算，不能靠延后收获无限拓地。胜/败/弃的提交、挂露领取、痕耐久与光尘消费见 [冲突解决方案](issue-resolution.md) 的结算表。
