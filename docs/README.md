## 各文件如何协作

1. 设计规范负责玩法含义；数值表负责参数。两者冲突时登记问题，不用文件日期自行覆盖。
2. 存档契约负责序列化结构；建造计划只引用它，不再复制另一套schema。
3. 设定与文案必须符合玩法，但文案不能反过来新增资源来源、解锁门槛或能力。
4. 决策记录保存用户已确认的方向。冲突处理方案补齐执行方法；新增参数标为起调值，不把它们误称为已经实测或用户逐项指定。
5. 同一规则指定一个主定义，其余地方链接引用。原v6～v18是历史修订序列；发现与本轮已采纳方向冲突时，以现行正文为准。

## 状态用语

- **已实现**：当前代码可观察或已通过相应检查。
- **已定设计**：方向已确认，但可能尚未实现。
- **起调值**：已选为第一轮参数，仍须实测；不能宣称平衡已通过。
- **本轮落实方案**：为执行已确认方向而补齐的流程、字段、映射和文案，尚未实现。
- **待决策**：新的产品取舍确实需要用户选择时才使用；本轮列出的选择已全部回填。
- **待补规格**：工程或内容人员能在既定方向内完成，不再要求用户拍板。
- **历史**：保留追溯，不参与当前验收。
